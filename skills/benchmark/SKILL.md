# 성능 비교 실측 방법론

추천을 말하기 전에 아래를 전부 밟는다.

## 1. 경계부터 설계한다
결론이 조건에 따라 뒤집히는지 보는 게 측정의 목적이다. 질문에 적힌 형태 그대로만 재지 말고, 결론을 뒤집을 수 있는 변형을 최소 2개 실측에 넣는다:
- **사용 방식 변형**: 내장함수를 그대로 넘길 때 vs 람다·사용자 함수로 감쌀 때 (파이썬에서 함수 호출 방식은 승자를 뒤집는 대표 원인)
- **규모 변형**: 작은 입력(10^2)과 큰 입력(10^6)
- 질문엔 없어도 실무에서 흔한 사용 방식이면 변형에 넣는다.

## 2. 잡음보다 신호가 큰지 확인한다
- `timeit.repeat` 5회 이상, best(최솟값) 기준으로 비교한다 — 시스템 잡음을 거르는 표준 방식.
- 실행 순서를 바꿔 한 번 더 잰다. 순서를 바꿨더니 승자가 바뀌면 그 차이는 잡음이다.
- 차이가 잡음 폭 이내면 "사실상 동률"이라고 보고한다.

## 3. 조건부로 보고한다
- 경계에서 뒤집혔으면 단일 승자를 만들지 말고 "X 조건이면 A, Y 조건이면 B"로 추천한다.
- 측정 환경(파이썬 버전, 입력 규모, 반복 수)을 답에 명시한다.
