# 설명의 근거

설명이 맞는지는 네가 책임진다. 동작을 말하는 문장에는 바깥에서 온 근거를 붙인다. 근거가 없는 문장은 `짐작:`으로 표시하고, 사용자가 그 자리를 물으면 근거를 찾아 다시 답한다.

## 대상마다 쓰는 근거

설명하는 대상은 셋이다. **기제**는 안에서 어떤 상태가 언제 바뀌는지다. **주장**은 원문이 해냈다고 말하는 것이다. **자리**는 레포의 파일·디렉토리·경로 한 홉이다.

| 대상 | 근거 |
|---|---|
| 기제 | `lab/`에서 실험을 돌린 출력이다. 설계는 [`experiments.md`](experiments.md)를 따른다. 돌릴 수 없으면 원문 대목이나 소스의 `파일:줄`이다 |
| 주장(논문) | 주장을 받치는 원문 대목이다. 코드가 있으면 `lab/`에서 축소 재현한다([`source-paper.md`](source-paper.md)) |
| 주장(영상) | `sources/yt-<id>.md`의 `[mm:ss]` 원문이다. 그다음 저자의 현행 문서, 공식 문서, 원 논문 순이다. 돌려 볼 수 있는 기술 주장이면 기제처럼 실험한다 |
| 자리 | 코드 실행, 테스트 하나, `git log -S'<식별자>'`, blame 이다([`source-repo.md`](source-repo.md)) |
| 설계 이유(왜 이렇게) | 원저자 글, 설계 문서, 커밋·PR·이슈의 대목이다. 동작으로 답할 수 있는 왜("없으면 무엇이 깨지나")는 빼 보는 실험을 함께 쓴다 |

리서치는 지금 설명하는 문장 하나에 답하고 돌아온다. 원문 대목은 요약하지 않고 그대로 인용한다. 그래야 사용자가 네 해석과 원문을 견줄 수 있다. 쓰임새와 큰 그림 화면에는 출처 이름만 두고, 대목은 `map.md`를 만들거나 고칠 때 `## 쓰임새`와 `## 큰 그림`의 왜 줄에 쓴다. 확대 화면에는 문장마다 출처 이름을 달고, 대목은 답의 첫 줄을 받치는 것 하나만 보인다(영상 주장은 영상의 말까지 둘). 그 밖의 대목은 모두 세션 파일의 근거 줄에 둔다. 지난 세션 파일이나 `lab/`에 URL 과 함께 모아 둔 대목은 원문으로 쓰고, "지난 세션에 모은 대목"이라고 밝힌다.

## 고치는 법

사용자의 틀린 그림을 고치는 모양은 SKILL.md 의 설명의 모양에 있다. 피드백은 내용에 붙인다. "네 그림대로면 A 가 먼저인데, 대기 줄에는 B 가 먼저 들어갔다"처럼 말한다. 사람을 평가하는 말("아깝다", "잘했다")은 주의를 내용에서 자기로 옮긴다.
