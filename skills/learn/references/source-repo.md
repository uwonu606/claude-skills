# 남의 레포 갈래

상황은 남의 레포에서 짜임을 배우는 것이다. **네가 앞에 서고 사용자가 걷는다(walkthrough).** 사용자는 아직 이 레포를 혼자 읽을 숙련도가 없다. 어디를 열고 어느 줄을 볼지는 네가 찾아 주고, 읽고 말하는 것은 사용자가 한다.

## 줄기: 이유와 정찰 한 장

읽으려는 **이유**를 한 줄로 묻고, 답에서 갈래를 정한다. "짚이는 데가 있으면 말해 달라, 없으면 내가 잡는다"를 붙이고 멈춘다. 이유가 하려는 일이면 그것이 목적지다. 짜임을 보러 온 것이면 목적지는 비워 둔다.

| 갈래 | 이유의 모양 | 자리 칸의 단위 | 다음 칸은 어디서 | 끝 |
|---|---|---|---|---|
| 전체 짜임 | "무엇이 어디에 있고 어떻게 나뉘었나" | 디렉토리 하나, 또는 역할 하나(제품, 사람용 문서, 스크립트) | 정찰 한 장의 남은 줄에서 | 정찰 한 장의 줄을 다 지났을 때 |
| 한 가닥 | "X가 입력에서 출력까지 어느 파일을 거치나" | 경로의 한 홉(파일 하나의 한 자리에서 다음 파일로 넘어가는 곳) | 방금 본 코드가 넘어가는 자리에서 | 경로가 이유에 적힌 출력에 닿았을 때 |

정찰은 이름과 개수로만 잡고, 네 가지뿐이다.

```bash
git rev-parse --short HEAD; git status --porcelain
git ls-files | sed 's/.*\.//' | sort | uniq -c | sort -rn | head   # 확장자별 개수
git ls-files | cut -d/ -f1 | sort | uniq -c | sort -rn             # 최상위별 개수
head -60 README.md
```

진입점 후보는 이름으로만 본다. `package.json`·`pyproject.toml`·`Makefile`·`main.*`·`SKILL.md` 같은 것이다. 열어 보고 싶은 파일은 첫 칸이 맡는다.

`## 줄기`에 정체 한 줄(무엇을 하는 레포이고 무엇이 제품인가), 갈래, 이유, 정찰 넷의 출력 요약, 들어오기 전 `git status --porcelain`을 쓴다. `sources`에는 레포 경로와 HEAD를 쓴다. 첫 칸은 시작점과 그 이유 한 줄이다. 사용자가 짚은 데가 있으면 그것이 첫 칸이다.

**완료 기준**: `## 줄기`에 정체·갈래·이유·정찰이 있다. `sources`에 경로와 HEAD가 있다. 칸 1이 이유와 함께 정해졌다.

## 자리 칸

먼저 쓰기는 **본 것**이다. 칸을 열 때 네가 먼저 파일 한둘을 읽고, 사용자에게 셋을 준다.

1. 열 파일과 볼 줄 두셋(`파일:줄`). 플랜을 알아보는 첫걸음은 핵심 줄 한둘을 찾는 것인데, 숙련도가 없으면 그 줄을 못 찾는다.
2. 물음 하나. 예: "이 줄이 무엇을 하나", "이 디렉토리가 맡는 것이 무엇인가".
3. 확인 방법과 비용 한 줄. 돌려 볼 수 있으면(스킬 실행, 테스트 하나 써서 실행) 무엇을 돌리면 무엇이 보이는지 적는다.

사용자의 말이 코드와 어긋나면 `파일:줄`과 함께 그 자리에서 짚는다. 이 갈래에서는 가설을 기다리지 않고 바로 고쳐 준다. 안내자는 고쳐 주는 사람이다. 코드를 바꾸는 실험은 정찰의 `git status`에 안 잡힌 깨끗한 파일에만 하고, 칸을 닫기 전에 되돌린다.

**왜가 걸리면 바깥부터 본다.** "왜 이렇게 했지" 싶은 줄을 만나면, 그 식별자나 설정 키가 나타나는 다른 자리를 따라가 본 **뒤에** 답한다. 그 자리의 문서와 이름만으로 만든 답이 읽기가 틀리는 자리다. 실측에서 숙련자가 `IREC = 0`을 문서대로 "포인터 비우기"로 읽었는데, 실제 목적은 다른 루틴의 최적화를 막는 것이었다(Letovsky & Soloway 1986). 따라가서 없으면 이력을 판다(`git log -S'<식별자>'`, blame). 커밋·PR·이슈에 이유가 있으면 해시와 함께 **인용**하고, 없으면 **추측**과 blame이 가리키는 이름을 적는다.

다음 칸은 갈래의 단위로 고르고 이유 한 줄을 붙인다. 갈래의 끝에 닿으면 목적지 시험 대신 정리로 닫는다.

## 정리에 더할 것

세션을 닫을 때 `## 정리` 아래에 둘을 더하거나 갈아 쓴다.

- **옮길 것**: 이 레포에서 내 것에 가져갈 짜임이다. 되풀이되는 짜임에는 이름을 붙인다. 확립된 이름(포트와 어댑터, 커맨드 패턴)이 있으면 그것을 쓰고, 없으면 "이름 없음"으로 둔다. 사용자가 `본 것`에서 쓴 낱말로 적는다. 그다음 한 줄만 묻는다: "이 가운데 하나를 네 저장소의 어디에 옮겨 볼 수 있겠나?" 사용자가 해 보면, 돌린 출력만 `써 봄:`으로 붙인다.
- **안 본 것**: 전문을 읽은 파일, 일부만 본 파일, 이름만 본 것을 나눠 적는다. 다음 세션이 어디를 믿고 어디를 다시 볼지 아는 단서다.

**이을 때.** `sources`의 HEAD와 지금 HEAD가 다르면, `git diff --stat <HEAD>..HEAD -- <지도의 자리들>`을 돌린다. 바뀐 자리는 지도 줄에 `낡음? (<옛>→<새>)`로 표시하고, 그 자리는 새 HEAD로 읽는다. 바뀐 자리가 없으면 커밋 수만 한 줄로 말한다.
