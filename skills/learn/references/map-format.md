# 지도와 세션 파일 형식

```
git-rebase-history/
  map.md
  sessions/
    2026-10-26-1.md
    2026-10-27-1.md
  sources/          # 스크립트가 받은 원문만. 영상 전사 yt-<id>.md
  lab/              # 실험 코드와 출력
```

아래 예시의 `<원문 대목>` 자리에는 실제로 읽은 원문을 그대로 넣는다. 읽지 않은 대목을 지어 넣지 않도록 예시에도 비워 두었다.

## map.md

`map.md` 는 새 세션이 처음 읽는 파일이라 짧게 둔다. 설명에서 일어난 일은 세션 파일에 두고, 여기에는 큰 그림과 상태, 가리키는 경로만 둔다. 확대한 곳과 갈고리는 한 줄씩이다. frontmatter 의 `sources` 에는 논문·문서·레포·옛 노트의 경로나 URL 을 적고, 원문을 복사하지 않는다.

```markdown
---
topic: git rebase
slug: git-rebase-history
kind: tech                    # tech | paper | video | repo
status: open                  # open | done(사용자가 됐다고 함)
why: "PR 올리기 전에 지저분한 커밋을 정리하고 싶어"   # 사용자가 넘기면 없음
verdict: 그대로               # 그대로 | 대안 권함 | 없음(이유를 넘겼거나 옮긴 지도)
sources:
  - "git-rebase 문서 https://git-scm.com/docs/git-rebase"
  - "Pro Git 3.6 Rebasing https://git-scm.com/book/en/v2/Git-Branching-Rebasing"
sessions: [2026-10-26-1, 2026-10-27-1]
---

## 다음 세션                   # 5단계에서 갈아 쓴다
- 이어 갈 곳: 큰 그림의 'todo 목록' — 지난 세션이 커밋 다시 쓰기까지 확대했고, 흐름 순서로 다음 부품이다
- 갈고리: [todo 목록] 줄 순서를 바꾸면 커밋 순서가 바뀐다 · [reflog] rebase 로 사라진 커밋도 되살릴 수 있다
- 읽을 것: map.md, sessions/2026-10-27-1.md
- 환경: `cd lab && sh 02-rewrite.sh` (임시 저장소를 만들고 지운다)

## 쓰임새
- 무엇: 커밋 여러 개를 다른 밑동 위에 하나씩 다시 쌓는 명령 — git-rebase 문서 DESCRIPTION "<원문 대목>"
- 잘 맞는 곳: 아직 남과 나누지 않은 내 브랜치의 커밋 정리 — Pro Git 3.6 "<원문 대목>"
- 안 맞는 곳: 이미 push 해서 남이 받은 커밋. 다시 쌓으면 해시가 바뀐다 — Pro Git 3.6 "The Perils of Rebasing"
- 대안: 이력을 그대로 두고 합치기만 하면 merge 가 더 안전하다 · 커밋 하나만 고치면 commit --amend 가 더 쉽다 — 출처
- 판단: 그대로 — 이유가 "PR 올리기 전"이라 아직 나누지 않은 커밋이다

## 큰 그림
- 왜: <원문이 말한 문제 한두 줄> — <출처> "<원문 대목>"
- 부품:
  | 부품 | 맡는 일 | 주고받는 것 |
  |---|---|---|
  | 밑동(upstream) | 커밋을 다시 쌓을 자리 | rebase 가 여기서 시작 |
  | todo 목록 | 다시 쌓을 커밋과 할 일(pick·squash·drop)의 차례 | rebase 가 한 줄씩 읽음 |
  | 커밋 다시 쓰기 | 커밋 하나의 변경을 새 자리에 적용해 새 커밋을 만든다 | 새 해시 |
  | reflog | 브랜치가 가리켰던 옛 자리의 기록 | 되돌릴 때 씀 |
- 이 예시에서는 안 지난다: --onto, autosquash, rerere
- 한 판 따라가기: feature 의 커밋 셋 → todo 목록에 셋 → 하나씩 main 위에 다시 씀 → feature 가 새 커밋 셋을 가리킴 — `lab/01-rebase.sh` → out-01.txt

## 확대한 곳                    # 확대할 때마다 한 줄
- [커밋 다시 쓰기] "rebase 하면 커밋이 옮겨지는 거야?" → 옮겨지지 않고 새로 만들어진다. 옛 커밋은 reflog 가 가리킨 채 남는다 — sessions/2026-10-27-1.md
- [todo 목록] 갈고리: squash 하면 메시지가 둘 다 남는다 → 편집기에 두 메시지가 이어 붙어 열린다 — sessions/2026-10-27-1.md

## 갈고리                      # 아직 확대하지 않은 곳. 다음 세션에 걸 순서로
- [todo 목록] 줄 순서를 바꾸면 커밋 순서가 바뀐다 — 숨은 상태
- [reflog] rebase 로 사라진 커밋도 되살릴 수 있다 — 이 사용자에게 닿는 곳
- [커밋 다시 쓰기] 충돌이 나면 rebase 가 중간에 멈춘 채로 남는다 — 깨지는 곳

## 이유                        # why 를 바꿨을 때만. 옛 문장과 날짜

## 밖                          # 주제 밖이라 미룬 것
- git 내부의 객체 저장 방식
```

`확대한 곳`의 물음 자리는 둘이다. 사용자가 물었으면 사용자의 말을 따옴표 안에 그대로 둔다. 갈고리를 골랐으면 `갈고리:` 뒤에 그 갈고리를 따옴표 없이 둔다. 갈고리는 네 글이기 때문이다. 화살표 뒤는 네 글이다.

## sessions/<날짜>-<n>.md

```markdown
---
status: open                  # open | closed
---

## 쓰임새                      # 새 주제의 첫 세션만
- 보인 것: map.md 의 ## 쓰임새
- 이유: "PR 올리기 전에 지저분한 커밋을 정리하고 싶어"
- 판단: 그대로 — 아직 나누지 않은 커밋이다

## 큰 그림
- 보인 것: map.md 의 ## 큰 그림
- 근거: `cd lab && sh 01-rebase.sh` → out-01.txt
- 건 갈고리: [reflog] 사라진 커밋도 되살린다 · [커밋 다시 쓰기] rebase 하면 해시가 바뀐다 · [todo 목록] squash 하면 메시지가 둘 다 남는다

## 확대 1. 커밋 다시 쓰기
- 물음: "rebase 하면 커밋이 옮겨지는 거야?"
- 고친 그림: "옮겨진다"대로면 해시가 그대로여야 한다. 실제로는 셋 다 바뀌었다
- 설명 요지: rebase 는 커밋을 새로 만든다. 옛 커밋은 reflog 가 가리킨 채 남는다
- 근거: `cd lab && sh 02-rewrite.sh` → out-02.txt, 해시 a1b2→c3d4
- 새 갈고리: [커밋 다시 쓰기] 충돌이 나면 중간에 멈춘다
```

`물음`·`설명 요지`·`근거`는 확대마다 늘 있다. `고친 그림`·`새 갈고리`는 생겼을 때 더한다. 사용자가 물음 없이 "다음"이라고 했으면 `물음: 다음(흐름 순서)`로 적는다. 갈고리를 골랐으면 `물음: 갈고리: <그 갈고리>`로 적는다. 옛 지도를 옮긴 세션은 맨 앞에 `## 옮김`을 두고 무엇을 어디로 옮겼는지 적는다.

## 옛 노트 옮기기

옛 노트는 둘이다. lab-notes·yt-notes·repo-walk 의 노트와, 이 스킬의 옛 형식 지도(칸 표 `## 지도`, `## 정리`, `## 안개` 를 가진 `map.md`)다. 옛 노트는 읽기 전용 원문이다. 옛 형식 지도는 옮기기 전에 `map.old.md` 로 이름을 바꿔 두고, 새 `map.md` 를 쓴다. slug 는 옛 디렉토리 이름을 그대로 쓴다. 그래야 다음에 같은 낱말로 찾힌다.

**옮기는 기준은 일어난 일이다.** 옛 칸의 상태 낱말(열림·닫힘·됨)은 옛 스킬이 사용자의 설명을 기다리던 표시라서 새 지도에는 맞는 자리가 없다. 그래서 옛 세션 파일을 읽고, 그 칸에서 설명이 오갔는지(누가 설명했든)와 사용자가 다음으로 넘어갔는지를 본다.

| 옛 것 | 새 자리 |
|---|---|
| `destination`·`## 목적지`·`## 과제`·레포의 이유 | `why`. 바뀐 이력은 `## 이유` 에 날짜와 함께. `verdict` 는 `없음` |
| `kind` | 그대로 두되, `sources` 가 레포이고 `why` 가 짜임을 가져가려는 일이면 `repo` 로 바꾼다. `source-repo.md` 의 닫을 때 더할 것이 그 이유에 맞기 때문이다 |
| `## 줄기`·`## 정체` | `## 쓰임새` 와 `## 큰 그림` 의 재료. `## 쓰임새` 는 옛 노트로 채울 수 있는 줄만 채우고, 나머지 줄은 `(옛 노트에 없음)` 으로 둔다. 사용자의 말은 따옴표째 옮긴다 |
| 설명이 오간 칸 | `## 확대한 곳`. 옛 세션 파일에 남은 사용자 물음마다 한 줄. 물음이 없으면 `[부품] 옛 칸 N:` 뒤에 칸 문장을 따옴표 없이 둔다 |
| 설명이 오가지 않은 칸 | `## 갈고리`. 재료 자리에 `옛 칸 N` |
| `## 안개`·`모르겠다:`·`open_questions`·열린 물음 | `## 갈고리`. 재료 자리에 어디서 나왔는지. 물음은 물음 그대로 두고, 확인하지 않은 답을 지어 붙이지 않는다 |
| 영상의 판정 표 | `## 갈고리`. 비판·추가 정보가 붙은 주장을 먼저 두고, 사용자의 판정은 따옴표째 붙인다. 버림은 `## 밖` |
| `## 밖` | `## 밖` |
| 다음에 할 일 | `## 다음 세션` 의 이어 갈 곳. 옛 `map.md` 의 `## 다음 세션` 과 마지막 세션 파일이 다르면 마지막 세션 파일을 따른다 |

옮긴 뒤 센다. 옛 칸 수와 안개 줄 수의 합이, 새 `## 확대한 곳`(칸에서 온 것)·`## 갈고리`·`## 밖` 에 옛 것에서 온 줄의 합과 맞아야 한다. 칸 하나가 확대한 곳 여러 줄이 됐으면 하나로 센다.

마지막 세션 파일이 `status: open` 인 채로 옛 형식이면, 옮기기를 먼저 한다. 그 세션 파일에는 `status: closed` 와 `- 닫음:` 한 줄만 더하고, `## 다음 세션` 은 옮기는 자리에서 한 번만 쓴다.

옮긴 지도에는 `## 큰 그림` 이 없다. 그래서 옮긴 뒤 첫 세션은 SKILL.md 3단계로 큰 그림부터 그린다. `why` 가 있으면 쓰임새 화면과 이유 물음은 건너뛴다. `## 다음 세션` 의 `읽을 것` 은 옛 노트에서 이어 갈 곳에 해당하는 절만 가리킨다.

lab-notes 에서 옮긴 노트의 옛 `lab/` 실험을 다시 돌려야 하면, 옛 스크립트는 제자리에서 `python3 -I -B` 로 돌린다. 출력 경로만 이 주제의 `lab/` 로 준다. 스크립트는 옛 `lab/` 기준의 상대 경로(`repos/` 등)를 읽기 때문에, 옮겨서 돌리면 경로가 깨진다. 돌리는 명령은 `## 다음 세션` 의 `환경` 줄에 적는다. 이 스킬의 옛 형식 지도는 `lab/` 이 이미 제자리에 있으니 그대로 돌린다.
