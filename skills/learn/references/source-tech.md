# 기술·도구·개념 갈래

**의심이 출발점이다.** 기술도 기제도 주어진 것으로 받지 않는다.

## 줄기

기술의 왜와 첫 기제를 잡는다. 줄기는 그것 없이는 나머지가 붙을 곳이 없는 것이다.

**추측과 목적지를 받는다.** 넷을 한꺼번에 묻고 멈춘다.

1. 이 기술은 어떤 문제 때문에 생겼을 것 같은가.
2. 그 문제는 지금도 있는가.
3. 그때의 대안은 무엇이었나.
4. 이 기술로 하려는 일 한 문장. 이것이 목적지다.

모르면 모른다고 적게 한다. 추측 없이 읽은 것은 사용자의 모델 위에 얹히지 않는다.

**출처를 대조한다.** 답이 있는 대목을 찾아 원문 그대로 보여 준다. 요약을 읽으면 대조가 네 것이 되기 때문이다. 찾는 순서는 원저자의 글(블로그·발표) → 설계 문서(RFC·design doc·PEP) → 첫 릴리스의 README → 큰 버전 사이의 변경 기록이다. 사용자가 자기 추측과 대목을 견줘 무엇이 희석됐고 무엇이 남았는지 적으면, `## 줄기`에 사용자의 낱말 그대로 옮긴다.

**첫 칸을 고른다.** 기제는 "안에서 실제로 무슨 일이 일어나는가"다. 문법이나 API 이름이 아니라 어떤 상태가 언제 어떻게 바뀌는가를 본다. 목적지에 필요한 기제 가운데 줄기 하나를 지도의 칸 1로 적는다. 칸에는 숨은 상태(눈에 안 보이는데 동작을 정하는 것)와, 실험으로 드러낼 수 있는 관측할 것이 있어야 한다. 관측할 것이 없으면 쪼갠다. 나머지 기제는 물음이 서는 만큼만 칸으로 두고, 그 밖은 안개로 둔다.

**완료 기준**: `## 줄기`에 추측, 출처 대목, 희석된 것과 남은 것이 있다. 목적지가 있거나 비어 있다. 칸 1이 숨은 상태와 관측할 것을 갖는다.

## 기제 칸의 먼저 쓰기

[`experiments.md`](experiments.md)를 읽고 실험 하나를 설계해 `lab/`에 쓴다. 돌리기 전에 둘을 묻는다.

1. 이 기제가 없으면 무엇이 깨질 것 같은가.
2. 출력 예측과, 그 예측이 맞을 거라고 얼마나 믿는지(높음/낮음).

가르기의 장치는 이 실험의 실행이다. 결과와 함께 숨은 상태를 찍어 보여 준다.

## 다음 칸

닫힌 칸에서 걸린 것에서 다음 칸을 고른다. 학생이 남긴 빈칸, 어긋난 예측이 가리킨 다른 상태, 목적지에 다음으로 필요한 것이 후보다. 물음이 서면 칸으로, 아직이면 안개로 올린다.
