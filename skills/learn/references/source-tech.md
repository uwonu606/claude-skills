# 기술·도구·개념 갈래

## 원문

쓰임새 화면 전에는 공식 문서의 소개와 비교·한계 절만 읽는다. 이유를 들은 뒤, 큰 그림에 필요한 만큼 원저자의 글(블로그·발표) → 설계 문서(RFC·design doc·PEP) → 공식 문서의 quickstart 와 이유에 닿는 절 → 첫 릴리스의 README → 큰 버전 사이의 변경 기록 순으로 더 읽는다. 원저자의 글과 설계 문서에 왜와 버린 대안이 있고, 공식 문서에 지금의 쓰임새가 있다. `sources` 에 찾은 것의 URL 을 적는다.

## 쓰임새

| 줄 | 재료 |
|---|---|
| 무엇 | 공식 문서의 첫 문단을 한 줄로 줄인다 |
| 잘 맞는 곳 | 원저자 글이 풀려던 문제, 공식 문서의 "when to use"·use cases |
| 안 맞는 곳 | 문서의 limitations·caveats, 이슈에서 되풀이되는 실패, 기제에서 따라 나오는 한계(스레드 하나면 CPU 일에 안 맞는다) |
| 대안 | 같은 문제를 푸는 다른 도구와, 대안이 이기는 조건. 원저자 글의 비교, 공식 문서의 비교 절, 설계 문서의 rejected alternatives |

기술이 낡았거나 관리가 멈췄으면 안 맞는 곳에 적는다. 마지막 릴리스 날짜, 저장소의 archived 표시, 공식 후속작이 근거다.

**완료 기준**: 네 줄에 출처가 하나씩 있다. 대안 줄에 이기는 조건이 있다.

## 큰 그림

- **왜**: 원저자 글이나 설계 문서에서 문제를 세우는 대목이다. 둘 다 못 찾으면 공식 문서의 소개 페이지를 쓰고, 그렇게 했다고 출처에 밝힌다.
- **한 판 따라가기**: 공식 quickstart 크기의 가장 작은 실제 사용 예 하나가 입력부터 출력까지 거치는 기제의 차례다. 이 예시를 `lab/`에서 돌려 출력과 숨은 상태 한두 개를 붙인다. 이유가 있으면, 이유가 하려는 일에 가장 가까운 예를 고른다.
- **부품**: 그 차례가 지나는 기제마다 맡는 일 한 줄과 주고받는 것이다. 이름은 공식 문서가 쓰는 이름을 쓴다.

## 확대

기제를 확대할 때는 그 기제의 숨은 상태를 찍는 실험을 [`experiments.md`](experiments.md)대로 짠다. 사용자가 "이게 왜 있나"를 물으면 빼 보는 실험을 쓴다.
