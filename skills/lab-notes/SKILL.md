# 실험 노트로 기술 익히기

한 번 실행에 기술 하나를 다룬다. 만드는 것은 기술이 왜 있고 안에서 어떻게 도는지에 대한 사용자의 이해다. 이해했다는 느낌은 재료가 아니다. 재료는 넷이다: 출처를 읽기 전에 적은 **추측**, 돌리기 전에 적은 **예측**, 실행이 보여 준 **상태**, 코드를 가리고 쓴 **설명**. 노트는 그 넷의 기록이다.

저장 위치는 `$LAB_NOTES_HOME`, 없으면 `~/lab-notes/`. 기술 하나가 `<slug>/notes.md` 이고 실험 코드는 `<slug>/lab/` 에 둔다. 형식은 [`references/notes-format.md`](references/notes-format.md).

**의심이 출발점이다.** 기술도 기제도 주어진 것으로 받지 않는다.

**한 턴에 한 걸음, 멈추고 기다린다.** 추측·예측·가설·설명은 사용자가 쓴다. 대신 써서 이으면 노트가 사용자 것이 아니게 된다.

## 1. 입구

- **기술 이름** — 저장 위치에서 같은 기술의 slug 를 찾는다. 없으면 2단계. 있으면 `notes.md` 를 끝까지 읽고 frontmatter 의 `status` 로 간다. `cycling` 이면 3단계를 잇는다. 마지막 회차가 안 끝났으면 그 회차의 빈 줄부터, 끝났으면 그 회차의 `모르겠다:` 를 재료로 다음 기제부터. `done` 이면 무엇을 더 볼지 묻고 `cycling` 으로 돌려 3단계로 간다.
- **인자 없음** — 저장 위치의 목록을 보여주고 하나 고르게 한다.

slug 는 기술과 다루는 면을 영문 kebab 2~4 단어로 적는다: `asyncio-event-loop`, `git-rebase`, `react-rendering`.

**완료 기준**: 어느 단계로 갈지 정해졌고, 이어서 하는 경우 `notes.md` 를 끝까지 읽었다.

## 2. 줄기

기술의 왜, 과제, 첫 기제를 잡는다. **줄기**는 그것 없이는 나머지가 붙을 곳이 없는 것이다. 줄기와 첫 실험은 같은 세션 안에 있어야 한다. 실험 전에 지도를 다 그리면 처음 보는 기술 앞에서 의지가 먼저 꺾인다.

**추측과 과제를 받는다.** 넷을 한꺼번에 묻고 멈춘다: 이 기술은 어떤 문제 때문에 생겼을 것 같은가, 그 문제는 지금도 있는가, 그때의 대안은 무엇이었나, 그리고 이 기술로 당장 하려는 것 한 문장. 모르면 모른다고 적게 한다. 추측 없이 읽은 것은 사용자의 모델 위에 얹히지 않는다. 과제가 없다고 하면 사용자의 일과 현재 저장소에서 하나 제안하고 확인받는다. 과제는 목표가 아니라 점검 장치다. 실험을 고르는 범위이고, 마지막에 이해를 시험하는 자리다.

**출처를 대조한다.** 답이 있는 대목을 찾아 **원문 그대로** 보여준다. 요약하지 않는다. 요약을 읽으면 대조가 네 것이 된다. 찾는 순서는 원저자의 글(논문·블로그·발표) → 설계 문서(RFC·design doc·PEP) → 첫 릴리스의 README → 큰 버전 사이의 변경 기록이다. 사용자가 자기 추측과 대목을 견줘 무엇이 희석됐고 무엇이 남았는지 적으면 `## 줄기` 에 사용자의 낱말 그대로 옮긴다.

**줄기 기제를 고른다.** 기제는 "안에서 실제로 무슨 일이 일어나는가"다. 문법이나 API 이름이 아니라, 어떤 상태가 언제 어떻게 바뀌는가. 과제에 필요한 기제 가운데 줄기 하나를 골라 `## 지도` 의 첫 줄로 적는다. **숨은 상태**는 눈에 안 보이는데 동작을 정하는 것이고, **관측할 것**은 실험으로 드러낼 수 있는 출력·순서·상태다. 관측할 것이 없으면 쪼갠다.

`notes.md` 를 만들고 `status: cycling`. 멈추지 않고 3단계로 간다.

**완료 기준**: `## 줄기` 에 추측·출처 대목·희석된 것과 남은 것이 있고, `## 과제` 에 한 문장이 있고, `## 지도` 에 첫 줄이 있다.

## 3. 회차

회차 하나는 기제 하나다.

**낸다.** [`references/experiments.md`](references/experiments.md) 를 읽고 실험 하나를 설계한다. 실험 코드는 `lab/` 에 쓴다. 사용자에게 **돌리기 전에** 둘을 쓰라고 하고 멈춘다: 이 기제가 없으면 무엇이 깨질 것 같은가, 그리고 출력 예측과 확신(높음/낮음).

**답이 오면** 다음 말을 보내기 전에 셋을 한다.

1. **기록한다.** `없으면:` 과 `예측:` 에 사용자의 낱말 그대로 옮긴다. 세션이 끊겨도 사용자의 말이 디스크에 남는다.
2. **돌린다.** 사용자가 돌리게 하거나 네가 돌린다. 결과와 함께 숨은 상태를 보여준다. `결과:` 에 적는다.
3. **가른다.** 맞았으면 설명으로 간다. 어긋났으면 "이 결과를 설명할 가설"을 사용자가 먼저 내게 하고 멈춘다. 가설이 오면 [`references/feedback.md`](references/feedback.md) 대로 짚는다.

**설명.** 코드를 가리고 기제를 제 말로 설명하게 한다. 물음은 "왜 그렇게 되는가" 하나뿐이다. 무엇이 들어가야 하는지는 네가 쥐고 있다가 판정에 쓴다. 미리 말하면 설명이 빈칸 채우기가 된다.

**되묻는다.** 설명에서 **핵심**을 뽑을 때까지 되묻는다. 핵심은 숨은 상태와, 그것이 없으면 깨지는 것이다. 되물음의 모양은 `feedback.md` 대로. 한 번에 하나, 상한 셋, "모르겠다"가 나오면 멈춘다. 되물음과 답을 `되물음:` 에, 모르겠다는 `모르겠다:` 에 적는다. 모르겠다가 다음 실험의 재료다.

**판정.** `feedback.md` 의 기준으로 판정하고 근거를 적는다. 핵심을 한 문장으로 말했으면 지도의 상태를 `됨` 으로 바꾼다. 아니면 같은 기제로 실험을 바꿔 회차를 하나 더 돈다.

**다음 기제.** 이 회차에서 걸린 것에서 고른다: `모르겠다:`, 어긋난 예측이 가리킨 다른 상태, 과제에 다음으로 필요한 것. 지도에 줄을 더하고 회차를 연다. 걸린 것이 없고 과제에 더 필요한 것도 없으면 4단계로 간다. 사용자가 끊으면 4단계의 정리로 바로 간다.

**완료 기준**: 회차마다 `없으면`·`예측`·`결과`·`설명`·`되물음`·`판정` 이 있고 판정에 근거가 있다. 지도의 상태가 갱신됐다.

## 4. 닫기

**과제 시험.** 사용자가 과제 또는 그 첫 조각을 실제로 해 보게 한다. 걸리면 그 기제로 회차를 하나 더 돈다. 해내면 `status: done`.

**정리.** `## 정리` 를 맨 위에 쓴다. 있으면 갈아 쓴다. 순서는 의심한 것과 찾은 왜, 처음에 어떻게 예측했고 무엇이 고쳐졌는지, 남은 모르겠다. 사용자의 낱말로. 끊어서 온 경우 `status` 는 `cycling` 그대로다. 다음에 부르면 1단계가 마지막 `모르겠다:` 로 데려간다.

**완료 기준**: `## 정리` 가 맨 위에 있고 줄마다 근거가 줄기나 회차에 있다. `status` 가 길에 맞다: 시험 통과면 `done`, 끊음이면 `cycling`. 사용자가 정리를 받았다.
