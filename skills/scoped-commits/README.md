# scoped-commits

커밋 하나가 **혼자 정당화되는** 변경이 되게 나누고, 무엇을 했는지가 아니라 **어느 영역을 건드렸는지**를 제목 앞에 세운다. 제목은 `<scope>: <설명>`, 본문은 모든 커밋에 쓴다.

이 문서는 **구조와 왜**를 적는다. 규칙 원문과 값 — 제목 폭, type 목록 — 은 [`references/messages.md`](references/messages.md) 에 살고 여기서는 링크만 한다. 같은 값을 두 곳에 적으면 갈리고, 갈린 것을 아무도 알아채지 못한다. 이 저장소가 실제로 밟은 구멍이다 — 제목 폭 값이 여러 곳에 갈린 채 남아, 규칙을 위반한 제목이 그대로 안착했다.

## 구조

| 층 | 어디 | 하는 일 |
|---|---|---|
| 의미 | [`SKILL.md`](SKILL.md) | 워킹트리를 **무엇을 한 커밋으로 묶을지**로 나눈다 |
| 형식 | [`references/messages.md`](references/messages.md) | scope·제목·본문을 **어떻게 쓸지**. 규칙 원문이다 |
| 재작성 | [`references/rewriting.md`](references/rewriting.md) | 이미 만들어진 커밋을 **어떻게 되돌려 다시 쓸지** |
| 점검 | [`references/log-audit.md`](references/log-audit.md) | 이미 안착한 로그에서 **표류를 어떻게 찾을지** |

읽는 시점으로 갈린 층이다. 분할이 확정되기 전에 형식 규칙을 읽으면 분할이 흔들린다.

## 설계 판단

**층을 가로지르는 판단만 여기 있다.** 한 층 안에서 닫히는 것 — 절차가 언제 승인을 받는지, scope 를 어떻게 고르는지 — 은 그 층의 문서가 갖는다.

### type 접두어를 버리고 scope 를 앞에 둔다

`feat:`·`fix:` 같은 type 은 대체로 한 값에 쏠려서 제목의 앞자리만 먹는다. 로그를 훑는 사람이 알고 싶은 것은 변경의 종류가 아니라 어느 영역을 건드렸는가다. 그 자리를 영역 이름에 준다.

이 형태는 지어낸 것이 아니라 큰 저장소들이 실제로 쓰는 것이다. Linux·FreeBSD·Git·Go·nixpkgs·Node.js 의 비머지 커밋 413건에서 `<scope>: <설명>` 형태가 95%, type 접두어가 3%, 마침표로 끝나는 제목이 0%, 72칼럼을 넘는 제목이 1%였다(2026-08-22). 다시 재려면:

```bash
gh api "repos/<owner>/<repo>/commits?per_page=100" \
  --jq '.[] | select(.parents|length < 2) | .commit.message | split("\n")[0]'
```

### scope 는 통 이름이 아니다

`src`·`lib`·`test`·`deps` 처럼 파일을 담는 통의 이름은 그 통 안의 **모든 커밋에 같은 이름이 붙어** 아무것도 좁혀 주지 못한다. scope 는 이 커밋이 바꾼 함수·상수·규칙의 공통 목적을 가리키는 이름이다.

**경로인지 아닌지는 기준이 아니다.** 위 여섯 프로젝트에서 scope 가 덮는 파일 비율의 중앙값은 Git 0.06%, Linux 0.06%, Node 0.07%, Go 0.94% 인데, 상위 이상치는 예외 없이 통 이름이었다 — Node `deps` 71%, Linux `drivers` 55%, Go `test` 22%. 반대로 Go 는 scope 의 84%가 경로형이고(`net/http/cookiejar`) 그것들이 가장 좁다. 갈리는 축은 경로냐가 아니라 **통이냐 영역이냐**다.

한 파일 안에 여러 영역이 살기 때문에, 같은 파일을 건드렸다는 사실은 같은 영역이라는 근거가 되지 못한다.

### 이름은 그 영역을 부르는 대로 쓴다

한때 scope 를 소문자 kebab-case 로 못박았다. 같은 여섯 프로젝트에서 그 형태에 맞는 scope 는 56% 뿐이다 — `net/http`, `drm/xe`, `nixosTests.fail2ban`, `MAINTAINERS` 가 전부 통용되는 이름이면서 그 규칙에 걸린다. 통용되는 이름이 있으면 그것이 맞고, kebab-case 는 새로 지을 때의 기본값이다.

### 분할을 정하는 동안 메시지 규칙을 읽지 않는다

이 스킬에서 가장 독특한 설계다. `SKILL.md` 는 분할이 확정된 뒤에 `references/messages.md` 를 열라고 명시한다.

컨텍스트에 무엇이 있느냐가 판단을 흔들기 때문이다. 같은 변경에 의미 규칙만 줬을 때와 메시지 규칙을 함께 줬을 때 커밋 수가 갈리는 것을 실측했다 — 수치는 그 지시가 있는 [`SKILL.md`](SKILL.md) 가 든다. 메시지 규칙은 "이렇게 쓸 수 있는 단위"를 떠올리게 해서 분할을 그쪽으로 끌어당긴다.

그래서 규칙을 한 파일에 몰아넣지 않고 **읽는 시점으로 갈랐다.** 형식 규칙이 `references/` 에 있는 것은 분량 때문이 아니라 순서 때문이다.

### 수치는 근거가 필요한 자리에 둔다

세상에 대한 사실은 문서에, 이 저장소가 왜 그 선택을 했는지는 커밋 본문에 둔다. 모델이 바뀌면 낡을 자기 벤치마크를 문서가 현재값인 척 들고 있지 않게 하려는 것이다 — 위 OSS 413커밋 수치가 문서에 남는 것은 그것이 세상에 대한 사실이기 때문이다.

예외가 하나 있다. **지시의 근거로 쓰이는 수치는 그 지시 옆에 남긴다.** `SKILL.md` 가 "3단계를 끝내기 전에 열지 마라"고 할 때 커밋 수가 갈린 실측을 함께 들지 않으면 그 지시가 임의로 읽힌다. `SKILL.md` 는 설계상 이 문서를 가리키지 않으므로 링크로 대체할 수도 없다. 그래서 그 수치만 커밋 본문으로 내리지 않았다.

### 규약은 스킬과 문서로만 전달한다

한때 이 저장소는 `commit-msg` 훅으로 규약을 강제했다. 그 층을 걷었다.

훅이 지킬 수 있는 것은 정적으로 판정되는 형식뿐이다. 되돌릴 수 없는 것 — 본문에 **왜 했는지가 적혔는가** — 은 정적으로 판정할 수 없어서, 훅은 존재만 보고 통과시켰다. 반대로 규약을 아는 주체 앞에서는 걸러 낼 것이 없었다. 이 저장소의 커밋에서 훅이 실제로 거부한 것은 없다.

스킬은 그 반대다. 컨텍스트에 있으면 분할과 본문 내용까지 만들고, 없으면 아무것도 하지 못한다. 두 층을 겹치는 대신 **스킬이 하는 일에 걸었다.** 다른 도구가 만드는 커밋을 막을 방법은 이제 없다.

### 재작성은 갈래를 먼저 가른다

이미 쓴 커밋을 고치는 길이 둘인데 성질이 다르다. 메시지만 고치는 `rebase -i reword` 는 작성일을 그대로 두고, 분할부터 다시 하는 `reset --soft` 는 새 커밋을 만들므로 작성일이 오늘이 된다 — 커밋 셋을 고쳐 재 보면 3/3 보존 대 0/3 이다. 작성일은 diff 에서 복구되지 않으므로, 애매하면 잃지 않는 쪽이 기본값이다.

이 갈래를 `SKILL.md` 에 함께 두지 않고 문서를 갈랐다. 3단계의 승인 규칙이 "분할이 틀리면 `reset --soft` 한 줄로 풀린다" 에 기대는데, 그 논거는 작업 전후로 HEAD 가 같을 때만 성립한다. 재작성은 그 전제를 깨므로, 한 파일에 두면 같은 절차 안에서 안전 성질이 두 갈래가 된다.

### 본문을 필수로 둔다

무엇을 했는지는 diff 가 말한다. 본문이 말해야 하는 것은 diff 에 없는 세 가지다 — 왜 했는가, 고려했다가 하지 않은 것과 그 이유, 확인하지 못한 것. 특히 두 번째가 없으면 다음 사람이 그것을 **빠뜨린 것으로 읽고 채워 넣는다.**

## 알고 남긴 구멍

**규약을 어긴 커밋을 막는 것이 없다.** 스킬이 컨텍스트에 없으면 — 다른 도구가 커밋하든, 사람이 손으로 쓰든 — 아무것도 걸리지 않는다.

**이미 안착한 커밋은 로그를 훑어야 찾는다.** 커밋 시점에 알려 주던 층이 없어졌으므로, 표류를 알아채는 것은 사후 점검이다 — [`references/log-audit.md`](references/log-audit.md). 그 점검은 형태와 type 접두어까지만 보고 폭·종결·본문은 놓친다.

**고치지 않은 것이 아니라 알고 남긴 것이다.** 어디까지 막히는지 알고 쓰는 것과 다 막힌다고 믿고 쓰는 것은 다르다.

## 어디를 볼 것

- [`SKILL.md`](SKILL.md) — 워킹트리를 커밋으로 만드는 절차. Claude Code 에서 `/scoped-commits` 로 부르거나 그냥 커밋을 요청하면 이걸 따른다
- [`references/messages.md`](references/messages.md) — scope·제목·본문 규칙 원문. 사람이 손으로 커밋할 때도 여기가 기준이다
- [`references/rewriting.md`](references/rewriting.md) — 이미 쓴 커밋을 다시 쓰는 두 경로와 그 대가
- [`references/log-audit.md`](references/log-audit.md) — 이미 안착한 로그에서 표류를 찾는 grep
