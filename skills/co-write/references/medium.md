# 장르별 기본

예전 글, 사용자가 명시한 요구, 회사·채널의 양식이 이 파일보다 앞선다.

첫 줄에는 독자가 읽자마자 할 일에 쓰는 것을 둔다. 바로 행동할 독자에게는 청하는 것이나 결론과 기한을, 흐름을 따라 읽는 독자에게는 독자가 겪는 문제나 글의 계기를 둔다.

말투와 모양은 따져서 나오지 않는 관례다. 독자가 그 장르에서 기대하는 모양이라서 그대로 따른다.

| 장르 | 기본 말투와 관례 |
|---|---|
| 슬랙 공유·장애 공유 | 합쇼체 개조식. 채널의 머리표 관례(`[공유]` 같은 것). 독자 무리마다 할 일은 줄을 따로 둔다 |
| 윗사람에게 보내는 업무 메일 | 합쇼체. 근거는 개조식 몇 줄. 자기소개와 서명은 예전 글에 있을 때만 |
| 결정 요청 | 합쇼체. 고를 것과 답할 기한을 제목에도 둔다 |
| 공지 | 합쇼체. 바뀌는 때를 날짜로 |
| 다른 팀에 보내는 요청 | 합쇼체, 인사 한 줄, 정중하되 짧게 |
| 팀 위키·제안 글 | 해요체 짧은 문단. 끝에 의견을 청한다 |
| 사내 블로그·공유 글 | 해라체('~했다') 문단 |
| 보고서·계획서 | 개조식. 항목은 '~함'·'~예정'으로 맺는다 |

## 높임

- 높임은 읽는 사람을 기준으로 한다. 팀장에게 쓰는 메일에서 다른 팀을 가리킬 때는 높이지 않는다: "재무팀에는 아직 확인하지 못했습니다".
- 청하는 글은 청으로 맺는다("부탁드립니다"). "~해 주시면 좋겠습니다"처럼 바람을 말하는 꼴은 청을 약하게 한다. 사용자가 고른 맺음말이 있으면 그 말을 쓴다.

## 날짜와 숫자

- 날짜 표기는 한 글 안에서 하나로 맞춘다(`10/27(화)` 또는 `10월 27일`). 요일을 붙이면 달력으로 확인한다.
- 시각 범위는 시작과 끝을 함께 적는다. 대략이면 사용자의 말 그대로 "경"이나 "쯤"을 붙인다.
