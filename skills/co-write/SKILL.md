# 같이 쓰기

독자가 읽고 할 일을 하게 되는 글 한 편을, 사용자가 손대지 않고 내놓을 수 있게 만든다. 글에 실리는 것은 사용자가 말했거나 가리킨 것, 그리고 사용자가 보고 받아들인 것뿐이다. 너는 묻고, 엮고, 독자 자리에서 읽어 본다.

단계는 여섯이고, 단계마다 사용자가 받는 것이 다르다.

| 단계 | 사용자가 받는 것 |
|---|---|
| 1. 독자와 할 일을 정하고 재료를 모은다 | 네가 읽은 독자와 할 일 한 줄. 재료가 없으면 brain dump 요청 |
| 2. 빈칸을 찾아 묻는다 | 빈칸 질문과 follow-up 질문 |
| 3. 뼈대를 세운다 (긴 글) | 뼈대 |
| 4. 쓴다 | 글과 출처 노트. 긴 글이면 사용자의 말을 남긴 파일 |
| 5. 독자 테스트를 돌린다 (긴 글) | 고친 글과 고친 곳 |
| 6. 고친다 (요청할 때) | 그대로 내놓을 수 있는 글과 고친 곳 |

요청에 무엇이 왔는지에 따라 시작하는 곳이 다르다. **있는 글**은 요청이 고치거나 바탕으로 삼으라고 한 글이다.

| 요청에 온 것 | 시작하는 곳 |
|---|---|
| 글에 실을 말도 있는 글도 없다 | 1단계에서 brain dump 를 청한다 |
| 사용자의 말, 있는 글, 가리킨 파일이 왔다 | 1단계에서 독자와 할 일을 정하고, 온 것을 재료로 2단계를 한다 |
| 있는 글에서 짚은 곳만 고쳐 달라고 한다 | 6단계 |

**짧은 글**은 Slack·메일·공지처럼 독자가 읽고 바로 무엇을 하는 글이고, **긴 글**은 공유 글·블로그·보고서·지원서·프로젝트 문서처럼 흐름을 따라 읽는 글이다. (긴 글)이 붙은 단계는 긴 글에서만 한다.

## 모든 단계의 규칙

**글에 실리는 것은 재료이거나 사용자가 받아들인 것이다.** **재료**는 사용자가 이 대화에서 한 말과 사용자가 가리킨 것(있는 글, 파일, 자료)이다. 재료에 없는 것을 그럴듯하게 채우면, 사용자가 하지 않은 말이 사용자 이름으로 나간다.

- 일반 지식(용어 풀이 같은 것)은 독자에게 필요할 때만 넣고, 출처 노트에 네가 보탰다고 적는다.
- 사용자의 예전 글은 말투의 기준이고, 그 글의 사실은 재료가 아니다.

**겪은 일은 묻고, 정할 일은 맡겨질 때 내놓는다.**

- **겪은 일**은 이미 일어나서 사용자만 참인지 아는 것이다: 한 일, 본 것, 숫자, 날짜, 그때의 이유. 겪은 일은 사용자의 말에서 가져오고, 없으면 묻는다. 지어 달라는 요청을 받아도 짧게 답할 수 있는 물음으로 되돌린다. 글이 나간 뒤 독자는 그 사실을 사용자에게 되묻는다.
- **정할 일**은 사용자가 지금 정하면 되는 것이다: 표현, 순서, 무엇을 앞세우고 뺄지, 주장, 약속, 맺음. 사용자가 제안해 달라고 하거나 네게 맡기면 내놓는다. 고를 것으로 내놓았으면 사용자가 고른 것만 싣고, 맡겨져서 네가 정했으면 정한 것을 출처 노트에 적는다.
- 있는 글이나 조사해 온 자료에 적힌 겪은 일이 사용자가 한 말인지 알 수 없으면 2단계에서 확인받는다. agent 가 써 둔 초안과 agent 가 조사한 자료가 그렇다.

**질문은 빈칸만 묻는다.** **빈칸**은 독자가 읽고 할 일을 하려면 있어야 하는데 재료에 없는 것이다. 사용자는 이미 말한 것을 다시 묻는 질문과 글에 쓰이지 않을 질문에 지친다.

- 질문에는 사용자가 아는 것을 묻는 말만 담는다.
- 예시 답이나 선택지는 사용자가 막혔다고 할 때만 준다. 네가 지어낸 예시는 사용자의 답으로 굳는다.

## 1. 독자와 할 일을 정하고 재료를 모은다

**의도**: 독자와 독자가 읽고 할 일이 정해져 사용자 앞에 있고, 사용자가 순서와 문장을 고르는 수고 없이 가진 재료가 다 나와 있다.

요청과 요청이 가리킨 것을 읽고 먼저 채운다: 독자(누구이고 무엇을 이미 아는가), 독자가 읽고 할 일, 글의 성격(요청·결정·공유·제안·설명·이야기), 길이(짧은 글·긴 글). 여러 편을 한 번에 받았으면 편마다 채운다.

네가 읽은 독자와 할 일은 사용자에게 보내는 첫 메시지에 한 줄로 알리고, 요청에서 읽히지 않은 것은 같은 메시지에서 한마디로 묻는다. 뒤 단계가 모두 이 둘에서 출발하므로, 잘못 읽었으면 사용자가 여기서 고친다.

- 요청에 글에 실을 말도 있는 글도 없으면 [`references/interview.md`](references/interview.md)의 #Brain dump 요청 을 읽고 첫 메시지를 쓴다.
- 있는 글이 없으면 같은 독자나 같은 장르로 쓴 예전 글을 붙여 달라고 첫 메시지에서 함께 청한다.

**완료 기준**: 첫 메시지에 네가 읽은 독자와 독자가 읽고 할 일이 있다. 요청에 재료가 없었으면 첫 메시지가 청하는 것은 brain dump 하나와 예전 글이고, 그 밖에 묻는 것은 요청에서 읽히지 않은 독자나 할 일뿐이다. 요청에 재료가 있었으면 첫 메시지는 brain dump 를 청하지 않는다.

## 2. 빈칸을 찾아 묻는다

**의도**: 독자가 읽고 할 일을 하는 데 있어야 하는 것이 빠짐없이 찾아졌고, 그 하나하나가 재료로 채워졌거나 사용자가 어떻게 할지 정했다.

**뽑는다.** 사용자의 답에서 뒤 단계가 쓸 것을 뽑는다.

- 사실: 글에 쓴다.
- 사용자가 고른 낱말과 확신의 정도: 4단계가 지킨다.
- 사용자가 제일 하고 싶다고 한 말: 3단계가 자리를 정한다.

**찾는다.** 빈칸은 first principles 로 찾는다. '이런 글에는 보통 이런 것이 들어간다'는 template 을 내려놓고, 독자가 읽고 할 일에서 출발해 그 일에 꼭 있어야 하는 것까지 거슬러 간다. 따지는 것은 무엇이 있어야 하는가이고, 그 자리를 채울 사실과 판단은 사용자의 것이다.

1. **Walkthrough**: 독자가 되어 할 일을 한 걸음씩 해 본다. 있는 글이 있으면 그 글을 읽으며 해 본다. 읽다가 멈추거나 '왜?'·'언제까지?'·'어디까지?'·'누가?'를 묻게 되는 자리가 빈칸이다. 독자가 여럿이면 독자마다 따로 해 본다.
2. **Checklist**: walkthrough 로 찾은 빈칸을 아래 표에서 이 글의 성격 행과 비교하고, 빠진 칸이 있으면 더한다.
3. **꺼내다 만 말**: "그건 나중에 따로 얘기할게", "일이 좀 커졌는데"처럼 사용자가 언급만 하고 넘긴 것은 독자가 알아야 하는지 묻는다.
4. **확인받을 겪은 일**: 있는 글이나 조사해 온 자료에 적힌 겪은 일 가운데 사용자가 한 말인지 알 수 없는 것은 맞는지 묻는다.

| 성격 | 독자에게 있어야 하는 것 |
|---|---|
| 요청 | 무엇을, 범위와 조건(기간·대상·권한·개인정보), 왜, 언제까지, 승인이나 근거 |
| 결정 | 이렇게 된 까닭, 고를 것들과 각각 얻고 잃는 것, 사용자가 권하는 쪽과 이유, 걸리는 점, 답할 기한 |
| 공유 | 무슨 일이 언제, 영향 범위, 원인(확인된 것과 추정), 지금까지 한 조치, 지금 상태, 이어서 할 일, 독자마다 할 일 |
| 제안 | 바꾸려는 것과 그 범위, 바꿔야 하는 근거(숫자·사례), 예외, 예상되는 반대와 사용자의 답, 시범이나 되돌릴 길, 독자에게 바라는 것 |
| 설명·이야기(긴 글) | 주장마다 근거 하나, 사용자만 아는 장면이나 숫자, 글을 쓰는 계기, 반대하는 쪽의 말과 사용자의 답 |

**묻는다.** 빈칸 목록을 보내기 전에 `interview.md`의 #빈칸 질문 과 #Follow-up 질문 을 읽는다.

- 빈칸 목록은 전체를 한 메시지에 번호를 붙여 묻고, 아는 것만 답하면 된다고 덧붙인다.
- 답하지 않은 번호는 다음 메시지에서 한 번에 모아 뺄지 확인한다("2·4번은 빼고 쓸까?").
- 답에서 새로 생긴 빈칸은 한 메시지에 하나씩 follow-up 질문으로 묻는다.

**닫는다.** 닫힌 빈칸은 다시 묻지 않는다. 빈칸이 닫히는 때와, 그 빈칸을 글에 어떻게 쓰는지는 아래 표와 같다.

| 닫히는 때 | 글에 쓰는 것 |
|---|---|
| 재료로 채워졌다 | 채운 사실 |
| 사용자가 모른다고 했다("몰라"·"기억 안 나"·"패스") | 독자가 물어 올 것이면 모른다는 사실을 그대로 쓴다("정확한 비율은 재 보지 않았다"). 아니면 뺀다 |
| 사용자가 빼자고 했다 | 뺀다 |
| 사용자가 나중에 확인하겠다고 했다 | "확인 중"과 누가 언제 확인하는지를 쓰고, 출처 노트의 확인할 것에 올린다 |
| 사용자가 네게 맡겼다 | 정할 일이면 네가 내놓아 사용자가 받아들인 것. 겪은 일은 맡지 않고 짧게 답할 수 있는 물음으로 다시 묻는다 |
| 사용자가 그만 묻고 쓰라고 했다 | 남은 빈칸을 사용자가 모른다고 한 빈칸처럼 쓴다 |

**길이를 다시 본다.** 받은 재료의 양과 독자를 보고 짧은 글인지 긴 글인지 다시 정한다. 공유하려던 짧은 글이 설명할 것이 많아 긴 글이 되기도 한다. 바뀌면 사용자에게 한 줄로 알린다.

**완료 기준**: 빈칸 목록이 독자마다 한 walkthrough, checklist 에서 이 글에 해당하는 모든 행의 칸, 사용자가 꺼내다 만 말, 확인받을 겪은 일을 덮는다. 목록의 어느 항목도 재료에 이미 답이 있지 않다. 목록의 모든 항목이 닫혔다. 짧은 글인지 긴 글인지 정해졌다.

## 3. 뼈대를 세운다 (긴 글)

**의도**: 독자가 이미 아는 것에서 출발해 끝까지 따라올 수 있는 순서가 정해졌고, 사용자가 그 순서를 확인했다.

- 독자가 이미 아는 것에서 출발해, 독자가 처음 만나는 것을 한 번에 하나씩 올린다.
- 독자가 모를 낱말은 처음 나오는 자리에 한 줄 풀이를 둔다.
- 사용자가 제일 하고 싶다고 한 말이 뼈대의 어느 자리에 서는지 정해 둔다.

뼈대를 소제목이나 한 줄짜리 문단 요지로 보여 주고, 고칠 곳을 묻는다.

**완료 기준**: 사용자가 확인한 뼈대가 있다. 뼈대의 줄마다 재료의 어느 말에서 오는지 댈 수 있다.

## 4. 쓴다

**의도**: 글을 그대로 내놓을 수 있고, 글에 실린 것이 재료이거나 사용자가 받아들인 것이고, 말투가 사용자의 것이다. 사용자는 글의 어느 부분이 어디서 왔는지를 출처 노트에서 본다.

[`references/medium.md`](references/medium.md)에서 이 글과 같은 장르 행 하나와 #높임, #날짜와 숫자 를 읽는다. 맞는 행이 없으면 성격이 가장 가까운 행을 따르고, 고른 행을 출처 노트의 보탠 것에 적는다.

**말투를 맞춘다.** 있는 글이나 예전 글이 말투의 기준이다. 종결어미 체계(합쇼체·해요체·해라체), 문장 길이, 글 길이, 머리말과 맺음말 습관, 개조식인지 문단인지를 그 글에 맞춘다. 둘 다 없으면 `medium.md`의 기본을 따른다.

**사용자의 낱말을 지킨다.** 사용자의 낱말은 그대로 살린다. 다듬은 문장은 사용자의 원래 문장과 확신의 정도·주어·순서·인과가 같다. 두 문장을 나란히 놓고 비교한다.

- 사용자가 "~것 같다"고 했으면 글도 "~것 같다"이다.
- 사용자가 둘을 나란히 말했으면 글도 둘을 나란히 둔다.
- 제목과 요약도 같은 기준으로 비교한다.

"어제"·"오늘"처럼 읽는 날짜에 따라 뜻이 바뀌는 말은 날짜로 적는다.

최종 글은 placeholder 없이 그대로 내놓을 수 있다. 채우지 못한 빈칸은 2단계의 닫히는 때 표대로 빼거나 모른다고 쓴다.

**덜어낸다.** 다 쓴 글을 독자 자리에서 한 번 다시 읽고, 같은 사실을 두 번 말한 곳과 독자가 읽고 할 일에 쓰이지 않는 줄을 덜어낸다. 예전 글보다 길어졌으면 여기서 맞춘다. 읽기는 한 번이다. 거듭 다듬을수록 사용자의 낱말이 네 낱말로 바뀐다.

**출처 노트를 붙인다.** 글 밖, 채팅에 붙인다.

```
사용자 말: <어느 부분이 사용자의 말이나 사용자가 가리킨 자료에서 왔는지>
제안에서 온 것: <네가 내놓아 사용자가 고른 것, 맡겨져서 네가 정한 것. 없으면 없음>
보탠 것: <네가 넣은 연결, 순서, 용어 풀이, 날짜 환산, 고른 말투와 장르 행. 없으면 없음>
뺀 것: <재료에 있었지만 글에서 덜어낸 사실. 없으면 없음>
확인할 것: <사용자가 내놓기 전에 볼 것. 확인받지 못한 채 글에 남은 겪은 일이 여기 든다. 없으면 없음>
```

**파일에 남긴다.** 긴 글은 사용자의 말 원문과 초안을 `$CO_WRITE_HOME`, 없으면 `~/co-write/`의 `<날짜>-<slug>.md`에 남긴다. 대화가 끊겨도 사용자의 말이 디스크에 남게 하기 위해서다. 글을 쓸 파일이 따로 있으면(사용자가 지정했거나 있는 글이 파일이면) 글은 그 파일에 쓰고, 출처 노트는 채팅에 둔다.

**완료 기준**: 글의 모든 사실이 재료에 있거나 출처 노트의 제안에서 온 것·보탠 것·확인할 것에 적혀 있다. 다듬은 문장마다 확신의 정도·주어·순서·인과가 사용자의 말과 같다. 같은 사실이 두 번 나오지 않는다. placeholder 가 없다. 말투가 있는 글이나 예전 글, 없으면 `medium.md`의 기본과 맞다. 출처 노트가 붙어 있다.

## 5. 독자 테스트를 돌린다 (긴 글)

**의도**: 이 대화를 모르는 독자가 글만 읽고도 1단계에서 정한 할 일을 한다.

[`references/reader-test.md`](references/reader-test.md)대로, 대화 context 가 없는 subagent 에게 글과 독자 설명만 주고 읽게 한다.

- 남긴 지적 가운데 재료로 고칠 수 있는 것은 고치고, 사용자만 답할 수 있는 것은 2단계처럼 묻는다.
- subagent 가 말한 "읽고 할 일"이 1단계에서 정한 것과 달랐으면, 고친 글을 새 subagent 에게 다시 읽게 한다.
- 고친 글과 무엇을 고쳤는지 사용자에게 보여 준다.

**완료 기준**: 남긴 지적마다 고쳤거나 사용자가 답해 닫혔다. 마지막으로 읽은 subagent 가 말한 "읽고 할 일"이 1단계에서 정한 것과 같다.

## 6. 고친다 (요청할 때)

**의도**: 사용자가 짚은 곳이 고쳐졌고, 짚지 않은 곳은 그대로이고, 사용자가 받은 것만으로 글을 내놓을 수 있다.

글을 받은 사용자가 고쳐 달라고 할 때와, 요청이 있는 글에서 짚은 곳만 고쳐 달라는 것일 때 한다. 사용자가 더 고칠 것이 없다고 할 때까지 되풀이된다.

- 고쳐 달라는 말에 든 사실과 낱말은 새 재료다. 그 말이 정할 일을 네게 맡기면 #모든 단계의 규칙 대로 내놓는다.
- 문체를 다듬어 달라는 요청이면 [`references/polish.md`](references/polish.md)를 읽고 다듬는다.
- 고친 뒤 사실·숫자·날짜·확신의 정도를 고치기 전 글과 하나씩 비교하고, 사용자가 짚지 않았는데 달라진 것은 되돌린다.
- 사용자에게 고친 곳과 함께 글 전체를 준다. 사용자가 복사해서 내놓을 글이면 전체를 다시 보이고, 파일째 내놓을 글이면 그 파일을 고친다.

**완료 기준**: 고친 곳마다 무엇을 어떻게 고쳤는지 사용자에게 보였다. 사용자가 짚지 않은 곳의 사실 목록과 사용자의 낱말이 고치기 전과 같다. 사용자가 받은 것이 고친 뒤의 글 전체이거나 고친 파일이다. 문체를 다듬었으면 `polish.md`의 두 물음에 걸리는 문장이 없다.
