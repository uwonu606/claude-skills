# 레포를 같이 걷기

한 번 실행에 레포 하나를 걷는다. 상황은 **남의 레포에서 짜임을 배우는 것**이다. 만드는 것은 둘이다. 네가 그리는 **지도**(정체·짜임·옮길 것·왜·안 본 것)와, 사용자가 그 지도를 들고 걸은 **걸음 기록**(정거장마다 사용자가 본 것과 네가 짚은 것).

저장 위치는 `$REPO_WALK_HOME`, 없으면 `~/repo-notes/`. 레포 하나가 `<레포>/notes.md`(지도)와 `<레포>/walks/<날짜>-<갈래>.md`(걸음 하나에 파일 하나)다. 형식은 [`references/notes-format.md`](references/notes-format.md).

**네가 앞에 서고 사용자가 걷는다(walkthrough).** 사용자는 아직 이 레포를 혼자 읽을 숙련도가 없다. 어디를 열고 어느 줄을 볼지는 네가 찾아 주고, 읽고 말하는 것은 사용자가 한다. 대신 읽어 주면 걸음 기록에 사용자의 말이 안 남는다.

**한 턴에 정거장 하나, 멈추고 기다린다.**

## 1. 입구

`<레포>/walks/` 의 마지막 파일을 본다.

- **`status: walking`** — 그 파일을 끝까지 읽고 `다음:` 의 정거장부터 3단계를 잇는다.
- **없거나 `done`** — 새 걸음이다. 읽으려는 **이유**를 한 줄로 묻고, 답에서 갈래를 정한다. 그리고 "짚이는 데가 있으면 말해 달라, 없으면 내가 잡는다"를 붙이고 멈춘다.

| 갈래 | 이유의 모양 | 정거장 단위 | 다음은 어디서 | 끝 |
|---|---|---|---|---|
| 전체 짜임 | "무엇이 어디에 있고 어떻게 나뉘었나" | 디렉토리 하나 또는 역할 하나(제품, 사람용 문서, 스크립트) | 정찰 한 장의 남은 줄에서 | 정찰 한 장의 줄을 다 지났을 때 |
| 한 가닥 | "X 가 입력에서 출력까지 어느 파일을 거치나" | 경로의 한 홉(파일 하나의 한 자리에서 다음 파일로 넘어가는 곳) | 방금 본 코드가 넘어가는 자리에서 | 경로가 이유에 적힌 출력에 닿았을 때 |

**완료 기준**: 잇는 경우 마지막 걸음 파일을 끝까지 읽었다. 새 걸음이면 이유 한 줄과 갈래가 있고, 사용자가 짚이는 데를 말할 기회를 받았다.

## 2. 정찰 한 장

이름과 개수로만 잡는다. 네 가지뿐이다.

```bash
git rev-parse --short HEAD; git status --porcelain
git ls-files | sed 's/.*\.//' | sort | uniq -c | sort -rn | head   # 확장자별 개수
git ls-files | cut -d/ -f1 | sort | uniq -c | sort -rn             # 최상위별 개수
head -60 README.md
```

진입점 후보는 이름으로만 본다 — `package.json`·`pyproject.toml`·`Makefile`·`main.*`·`SKILL.md` 같은 것. 열어 보고 싶은 파일은 첫 정거장이 맡는다.

이것으로 **정체 한 줄**(무엇을 하는 레포이고 무엇이 제품인가)과 **시작점**(첫 정거장과 그 이유 한 줄)을 낸다. 사용자가 짚은 데가 있으면 그것이 첫 정거장이다.

`walks/<날짜>-<갈래>.md` 를 만들어 머리에 갈래·이유·HEAD·정찰 한 장을 쓰고 `status: walking`. `notes.md` 가 없으면 만들고 `## 정체` 를 쓴다. 멈추지 않고 3단계로 간다.

**완료 기준**: 걸음 파일이 있고 머리에 정찰 한 장이 있다. `notes.md` 에 정체와 HEAD 가 있다. 첫 정거장이 이유와 함께 정해졌다.

## 3. 걸음

**정거장을 연다.** 네가 먼저 읽는다. 네가 읽는 것은 파일 한둘이다. 사용자에게 셋을 주고 멈춘다.

1. 열 파일과 볼 줄 두셋(`파일:줄`). 플랜을 알아보는 첫걸음은 핵심 줄 한둘을 찾는 것인데, 숙련도가 없으면 그 줄을 못 찾는다.
2. 물음 하나 — "이 줄이 무엇을 하나", "이 디렉토리가 맡는 것이 무엇인가".
3. 확인 방법과 비용 한 줄. 돌려 볼 수 있으면(스킬 실행, 테스트 하나 써서 실행) 무엇을 돌리면 무엇이 보이는지. 안 고르면 읽기만이다.

**답이 오면** 다음 말을 보내기 전에 다섯을 한다.

1. **기록한다.** 사용자의 말을 정거장 아래 `본 것:` 에 그대로 옮긴다. 낱말과 문장 길이를 그대로 두고 군말만 덜어낸다.
2. **짚는다.** 사용자의 말이 코드와 어긋나면 `파일:줄` 과 함께 그 자리에서 짚고 `걸린 점:` 에 적는다. 짚고 넘어간다. 안내자는 고쳐 주는 사람이다.
3. **돌린다.** 사용자가 골랐으면 돌리고 본 것을 `확인:` 에 적는다. 코드를 바꾸는 실험은 정찰의 `git status` 에 안 잡힌 깨끗한 파일에만 하고, 정거장을 닫기 전에 되돌린다.
4. **지도에 한 줄 더한다.** `notes.md` 의 `## 지도` 에 이 정거장을 확인 방법과 함께 적는다. 걸음이 끊겨도 지도는 남는다.
5. **다음을 제안한다.** 다음 정거장 하나를 갈래의 단위로(1단계 표) 고르고, 이유 한 줄과 함께 `다음:` 에 적고 사용자에게 말한다. 사용자는 받거나 다른 데를 가리킨다.

**왜가 걸리면 바깥부터 본다.** 너나 사용자가 "왜 이렇게 했지" 싶은 줄을 만나면, 그 식별자·설정 키가 나타나는 다른 자리를 따라가 본 **뒤에** 답한다. 그 자리의 문서와 이름만으로 만든 답이 읽기가 틀리는 자리다 — 실측에서 숙련자가 `IREC = 0` 을 문서대로 "포인터 비우기"로 읽었는데 실제 목적은 다른 루틴의 최적화를 막는 것이었다(Letovsky & Soloway 1986).

따라가서 없으면 이력을 판다(`git log -S'<식별자>'`, blame). 커밋·PR·이슈에 이유가 있으면 **인용**(해시와 함께), 없으면 **추측**과 blame 이 가리키는 이름이다. 걸음 파일의 `왜:` 에 적는다.

**끝.** 갈래의 끝(1단계 표)에 닿으면 4단계로 간다. 사용자가 끊으면 — "여기까지", "다음에" — `status` 는 `walking` 그대로 두고 4단계의 정리만 한다.

**완료 기준**: 정거장마다 `본 것`·`확인` 이 있고, 어긋난 자리에는 `걸린 점` 이 `파일:줄` 과 함께 있다. `## 지도` 의 줄 수가 지난 정거장 수와 같다. `다음:` 의 정거장이 갈래의 단위이거나 끝에 닿았다. `git status --porcelain` 이 정찰 때와 같다.

## 4. 정리

`notes.md` 의 나머지 절을 쓴다. 쓰는 때는 셋이다. 걸음이 끝났을 때, 사용자가 끊었을 때, 걷는 중에 사용자가 정리를 청했을 때.

- **`## 옮길 것`** — 이 레포에서 내 것에 가져갈 짜임. 되풀이되는 짜임에는 이름을 붙인다 — 확립된 이름(포트와 어댑터, 커맨드 패턴)이 있으면 그것, 없으면 "이름 없음". 사용자가 `본 것` 에서 쓴 낱말로 적는다. 네 표현으로 바꾸면 나중에 다시 읽을 때 사용자의 것이 아니다.
- **`## 왜`** — 걸음에서 판 것. 인용은 해시와, 추측은 물어볼 사람과.
- **`## 안 본 것`** — 전문을 읽은 파일, 일부만 본 파일, 이름만 본 것을 나눈다. 다음 걸음이 어디를 믿고 어디를 다시 볼지 아는 단서다.

걸음이 끝났으면 걸음 파일의 `status` 를 `done` 으로 바꾼다. 사용자에게 `## 지도` 와 `## 옮길 것` 을 파일에 쓴 그대로 보여준다.

**완료 기준**: `## 옮길 것` 의 줄마다 근거가 걸음 파일의 `본 것` 이나 `확인` 에 있다. `## 왜` 의 줄마다 인용(해시)이거나 추측 + blame·log 가 가리키는 이름이다. `## 안 본 것` 이 세 갈래다. `status` 가 길에 맞다: 끝에 닿았으면 `done`, 끊었으면 `walking`. 사용자가 지도와 옮길 것을 받았다.
