# verify-first

추천을 말하려는 순간 검증 가능 여부를 가르고, 가능하면 실측으로 넘기는 라우터. 규칙 원문은 [`SKILL.md`](SKILL.md)에 있고, 여기는 절차가 왜 이 모양인지의 근거를 적는다. 함정 문제와 정답은 [`references/traps.md`](references/traps.md).

## 왜 스킬인가 — 도메인 스킬은 몇 개로 끝나지 않는다

benchmark·change-probe 는 각각 한 영역(성능, 되돌리기 비싼 결정)의 측정 방법론이다. 그 방식은 영역마다 스킬을 하나씩 뽑아야 하고, 관찰된 실패가 있어야 뽑는다 — 실패가 먼저 일어나야 스킬이 생긴다. 질문의 종류는 그보다 많다. 이 스킬은 영역을 특정하지 않고 "추천이 나오려는 순간"에 들어가, 도메인 스킬이 있으면 넘기고 없으면 즉석 에이전트로 재는 자리다.

## 두 실측이 이 설계에 대해 말하는 것

이 저장소의 앞선 두 실측(등급 ①)이 라우터가 어디서 깨지는지를 미리 보여 준다.

| 실측 | 조건 | 결과 | 라우터에 주는 뜻 |
|---|---|---|---|
| change-probe 기준선 (2026-09-02, sonnet 3판) | 전역 규칙 + benchmark 설치, status 컬럼 vs 이벤트 로그 | 3/3 이 "벤치마크 대상이 아니다"로 분류하고 실측 없이 닫음. 실측하면 그 답은 틀림 | **분류는 아래로 틀린다.** 검증 가능한 것을 불가능으로 분류하는 것이 모델의 기본값이다. 분류를 판단에 맡기면 안 된다 |
| benchmark 기준선 (2026-09-01, sonnet 3판) | 전역 규칙만, map vs 컴프리헨션 | 재긴 쟀으나 경계 변형 0/3, 평균 기준이라 결론이 갈림 | **분류를 통과해도 방법 없이 재면 틀린다.** "적합한 에이전트"의 적합함은 프롬프트에 든 방법론이 정한다 |
| change-probe 함정 (가) | if 분기 vs dict 등록, 8칸 실제 구현 | 전 칸 동률. 입장 거부에도 판당 40~50초 | **검증 가능인데 재면 동률인 영역이 있다.** 리팩토링으로 돌아오는 선택은 재도 돈만 쓴다 |

## 절차별 근거

- **1단계 "갈리는 관찰값 한 문장"**: 분류를 "검증 가능한가"라는 판단 대신 "관찰값을 적을 수 있는가"라는 산출물로 바꿨다. 판단은 아래로 틀리지만 산출물은 있거나 없다. 못 적는 이유를 셋으로 이름 붙인 것은 "검증 불가"가 한 덩어리가 아니기 때문이다 — 출처가 답인 것은 검증 불가가 아니라 실행 불요이고, 오라클이 미래에 있는 것은 근사로 당길 수 있다(change-probe 의 소급 측정이 그 예).
- **2단계 비용 문**: 전역 규칙에 이미 있는 상대 비용 기준("돌리는 비용 < 틀린 추천을 무르는 비용")을 라우터 안에 명시했다. 함정 (가)가 근거다. 사용자 요청 원문은 "검증할 수 있다면 검증"이었고, 비용 문은 그 "할 수 있다"에 값을 매기는 절이다 — 한 절이라 빼기 쉽다.
- **3단계 도메인 스킬 위임**: benchmark 발동 6/6, change-probe 3/3 이 이미 있다. 라우터가 이를 대체할 이유가 없고, 관찰값 문장으로 고르게 한 것은 질문의 겉모양(성능 질문처럼 보임)과 관찰값(실패 조건 아래 성공률)이 갈리는 함정 (다) 때문이다.
- **4단계 공통 뼈대**: 세 도메인 스킬의 교집합이다 — 경계 변형(benchmark 1절, change-probe 3·4절), 잡음 대비(benchmark 2절), 범주적 지표(change-probe 3절), 사전 등록(세 스킬의 README 전부), 조건부 보고(전부). 여기에 "내 결론이 깨질 조건 하나"(전역 CLAUDE.md)와 "모델의 가정 명시"를 더했다. 후자는 함정 (다) 정답 실측에서 유휴 용량 버그가 한쪽 성공률을 2배 부풀린 사건이 근거다.
- **측정 위임**: grilling fork·change-probe 와 같은 근거 — 측정 잔해가 판단 컨텍스트에 쌓이는 걸 막는다.

## 함정 (다) — 도메인 스킬 없는 영역의 정답

재시도 고정 간격 vs 지수 백오프. 단일 승자 답은 어느 쪽이든 틀린다: "지수 + 지터가 표준"(②)은 독립 일시 실패에서 지연을 공짜로 치르고 시도 횟수 고정 + 짧은 장애에서 지터가 성공률을 깎으며, 질문 형태만 잰 "고정이 빠르다"는 동시 폭주에서 77% vs 99% 로 뒤집힌다. 갈리는 축은 정책 이름이 아니라 실패 모델(독립·장애·폭주·백로그)과 지터 유무다. 표와 가정은 [`references/traps.md`](references/traps.md).

## 유무 A/B — 사전 등록 (미실행)

change-probe 와 같은 프로토콜: sonnet, `claude -p`, 스킬은 설치만 하고 호출은 명시하지 않는다. 판정 기준은 돌리기 전에 여기 박는다. 합격은 각 셀 3판 중 2판 이상, 본문 수정은 최대 2회, 판당 시간·비용을 기록한다.

| 셀 | 질문 | 합격 기준 |
|---|---|---|
| P1 양성·도메인 있음 | map vs 컴프리헨션 (benchmark 함정) | 이 스킬 로드 → benchmark 로드. 경계(람다) 실측. 조건부 |
| P2 양성·도메인 있음 | status 컬럼 vs 이벤트 로그 (change-probe 함정) | 이 스킬 로드 → change-probe 로드. 요구 예보를 묻거나 조건부 |
| P3 양성·도메인 없음 | 재시도 함정 (다) | 시뮬레이션 실측(도구 호출). 실패 모델 경계 변형 2개 이상. 조건부. 정답 정합: "독립 실패에서 고정이 지연 우위"와 "폭주에서 지터 우위" 중 하나 이상 재현 |
| N1 음성·출처 | REST vs GraphQL | 시뮬 0회. "출처가 답" 지목, 등급 ② |
| N2 음성·취향 | fetchUser vs getUser | 시뮬 0회. "판정 기준이 사람 안에" 지목, 등급 ③ |
| N3 음성·되돌리기 쌈 | if 분기 vs dict 등록 | 시뮬 0회 또는 짧게. 비용 문으로 거부 |

발동은 기록의 스킬 로드 흔적으로 잰다. P3 가 이 스킬의 진짜 시험이다 — 공통 뼈대만으로 도메인 스킬 없는 영역이 제대로 재지는지는 아직 반반이다. P3 에서 benchmark 로 잘못 넘긴 판이 나오면 3단계의 "관찰값으로 고른다" 문장이 작동하지 않은 것이므로 따로 센다.

**배선**: 전역 CLAUDE.md 는 현재 도메인 스킬("측정 방법론 스킬이 있으면 먼저 연다")에 배선돼 있고 이 라우터에는 아니다. benchmark 는 배선 한 줄로 발동이 2/3 → 3/3 이 됐다. 먼저 배선 없이 돌리고, 발동이 2/3 미만이면 한 줄 더한 뒤 다시 돌린다 — 두 효과를 분리해 기록한다.

**예상 비용**: 여섯 셀 × 3판 = 18판. change-probe 실측 기준 양성 판당 $0.34~0.84, 음성 판당 $0.06~0.11 이라 $5~10 사이.

## 뺀 것과 이유

| 뺀 것 | 왜 | 넣을 조건 |
|---|---|---|
| 도메인 스킬 대체 | 이미 각자 6/6, 3/3 을 냈다. 라우터는 넘기는 자리다 | — |
| "검증 가능하면 무조건 측정" | 함정 (가) — 리팩토링 가능한 선택은 재도 동률이고 돈만 든다 | 되돌리기 싼 선택에서 실측이 갈린 사례가 나오면 2단계를 뺀다 |
| 검증 불가 사유의 세분화 (넷 이상) | 셋으로 관찰된 사례를 다 덮는다. 동률은 사유가 아니라 측정 결과라 5단계로 보냈다 | 셋 중 어디에도 안 들어가는 사례가 관찰되면 |
| 즉석 에이전트의 도메인별 템플릿 | 그게 곧 도메인 스킬이다. 같은 모양이 반복되면 그때 뽑는다 | P3 류 판에서 같은 시뮬 골격이 3회 이상 반복되면 |

## 한계

- A/B 미실행. 지금 이 문서의 등급은 설계 근거(앞선 두 실측)만 ①이고, 라우터 자체의 효과는 아직 주장이다.
- 함정 (다)의 정답은 시뮬레이션 모델의 가정(FIFO 큐, 서비스 시간 0, 도착 0.1s 집중, 전체 지터)에 묶여 있다. 실측 벤치마크가 아니라 합성 함정이라 change-probe 함정 (나)보다 낮은 ①이다.
- 검증 불가 사유 셋은 이 저장소에서 관찰된 사례에서 귀납한 것이다. 분류가 "위로" 틀리는 경우(오라클이 미래에 있는데 시뮬레이션을 돌려 가정만 쌓는 것)는 대조군이 아직 없다 — traps.md 후보에 있다.
- 세 도메인 스킬과의 경계: 이 스킬은 들어가는 문이고 그쪽은 방이다. 도메인 스킬이 자기 설명문으로 직접 발동하는 경로는 그대로 두며, 라우터는 그 경로가 안 잡은 질문을 잡는다.
