# Explore Model

**모델 검사**: 설계한 모델의 상태공간을 기계가 훑고, **반례**가 나오면 사람이 판정한다.

손으로 모는 프로토타입은 밟는 명령열이 수십 개고 전부 설계자가 상상한 것이다. 설계가 틀린 지점은 상상하지 못한 조합에 있다 — 상상했다면 설계할 때 이미 반영했다. 판정이 취향에 가까우면("이게 그럴듯한가") 손으로 몰아보는 편이 빠르다 — `/prototype` 이 그 절차다.

## Phase 1 — 불변식을 세운다

**이게 스킬의 전부다.** 나머지는 기계적이다. 날카로운 **불변식** 하나가 있으면 반례는 탐색이 알아서 찾아낸다. 불변식이 없으면 탐색은 상태 목록만 뱉는다.

불변식은 모든 도달 가능 상태에서 참이어야 하는 명제다. 코드를 다시 읽지 않고 문장으로 말할 수 있어야 한다.

### 출처 — 넷 중 하나를 지목한다

불변식의 진실성은 **모델 밖에서** 온다. 지목할 수 있는 출처는 넷뿐이다.

1. **사람** — 도메인 전문가에게 묻는다. 가장 강하고 가장 느리다.
2. **합의된 기록** — 용어집·ADR·스펙·티켓. 저장소가 이미 문서로 굳혀 둔 결정.
3. **참조 구현** — 기존 코드, 이전 버전, 명세 구현.
4. **변형 관계** — 왕복·멱등성·교환법칙. 도메인 지식 없이 성립한다.

출처를 지목한 명제만 목록에 올린다. 지어낸 명제로 판정하면 검증 대상이 설계가 아니라 지어낸 쪽의 이해가 된다.

**검사할 설계 문서가 유일한 기록일 때** — 이 스킬을 부르는 가장 흔한 상황이다 — 그 문서 안에서도 **의도와 기전을 가른다.**

- **의도는 출처가 된다.** "환불된 주문은 재결제되지 않는다" 처럼 문서가 요구사항으로 선언한 것. 전이표가 이걸 어길 수 있고, 어기면 그게 반례다.
- **기전은 출처가 아니다.** "cancel 은 NEW·PAID 에서" 처럼 모델이 어떻게 도는지를 적은 것. 여기서 뽑은 명제는 탐색이 반드시 참으로 만든다 — 모델을 모델 자신으로 검사하는 순환이라 반례가 나올 수 없다.

문서가 기전만 적고 의도를 안 적었으면 출처 2 는 비어 있는 것이다.

**순환인지는 탐색이 개입하는가로 갈린다.** 기전에서 불변식을 뽑으면 탐색이 그 명제를 반드시 참으로 만드니 순환이다. 반면 **기전끼리 모순임을 관찰하는 것은 순환이 아니다** — 탐색이 개입하지 않는 문서 일관성 검사이고, 문서가 양쪽을 다 선언했으므로 문서 자신이 근거다. 아래 문 2 의 둘째 길이 그것이다.

저장소에 용어집이 있으면 읽고 그 용어로 쓴다 — `/domain-modeling` 을 쓰는 저장소라면 `CONTEXT.md` 다.

### 완료 기준 — 승인된 불변식 목록

- [ ] 각 불변식이 한 문장이고, 반례를 보면 참/거짓을 즉시 판정할 수 있다
- [ ] 각 불변식에 출처가 넷 중 하나로 지목돼 있다
- [ ] 사용자가 목록을 승인했다

### 나가는 문은 셋이다

Phase 1 은 셋 중 하나로 끝난다. 어느 문으로 나가는지 보고 첫 줄에 적는다.

1. **승인** — 목록이 서고 사용자가 승인했다. Phase 2 로 간다.
2. **표현 불가능** — 두 길로 열린다. 어느 길이든 탐색하기 전에 이미 난 판정이므로 Phase 4 의 **표현 불가능** 갈래 형식으로 내고 멈춘다.
   - **출처 있는 불변식을 모델이 표현하지 못한다.** "환불 총액 ≤ 결제 총액" 을 요구사항에서 받았는데 상태에 금액 필드가 없다.
   - **문서가 선언한 기전을 문서가 선언한 상태로 그릴 수 없다.** 액션 절은 부분환불을 선언하는데 상태 절은 이름 다섯 개짜리 열거형이다. **이 길에는 출처가 필요 없다** — 위 순환 규칙대로 문서 자신이 근거다.

   실패가 아니라 가장 값싼 성공이다. 하네스를 한 줄도 짜지 않고 모델이 부족하다는 것을 알아냈다.
3. **출처 공백** — 네 출처가 다 비어 명제를 세울 수 없다. 무엇을 시도했고 어디가 비었는지, 그리고 **사람에게 물어야 할 질문 목록**을 적어 넘긴다. 불변식을 쓰려다 드러난 설계의 모호함이 그대로 그 질문이 된다.

2번과 3번이 겹치면 둘 다 낸다. 위 완료 기준 셋은 **문 1 로 나갈 때만** 판정한다 — 문 2·3 은 목록이 서지 못한 채 끝나므로 승인받을 것이 없다.

## Phase 2 — 기법을 고른다

기법은 **오라클이 어디서 오는가**와 **상태공간이 유한한가**로 갈린다. 위에서부터 싸고 확실하다.

| # | 기법 | 이럴 때 | 오라클 |
|---|---|---|---|
| 1 | 왕복 | 직렬화·저장·인코딩 | 공짜 (자기 자신) |
| 2 | 도달성 전수 탐색 | 상태기계·워크플로·권한 | 불변식 |
| 3 | 차등 실행 | 리팩토링·마이그레이션·재작성 | 참조 구현 |
| 4 | 순서 교환 | 명령 순서가 결과를 바꾸는지 의심스러울 때 | 불변식 |
| 5 | 인터리빙 | 동시 실행·경쟁 | 불변식 |
| 6 | 변형 관계 | 정답을 모를 때 | 출력 사이의 관계 |
| 7 | 무작위 + 축소 | 값 범위가 넓어 전수가 불가능할 때 | 불변식 |
| 8 | 결함 주입 | 재시도·타임아웃·부분 실패 | 불변식 |

각 기법의 하네스 작성법과 함정은 [`references/techniques.md`](references/techniques.md) 에 있다. **고른 기법의 절만** 읽는다.

둘 이상 고를 수 있다. 1번은 해당하면 항상 같이 돌린다 — 비용이 거의 없고 직렬화 버그를 잘 잡는다.

### 완료 기준

- [ ] 후보였다가 뺀 기법과 뺀 이유를 적었다

## Phase 3 — 범위를 좁히고 탐색한다

모델은 구현이 아니라 질문에 답할 만큼만 담는다. 순수 함수로 둔다 — I/O 없음, 출력 없음, 전역 없음. 이 리듀서가 탐색이 끝난 뒤 실코드로 올라갈 유일한 산출물이다.

**범위 축소는 기법이다.** 반례는 대부분 작은 **범위**에서 이미 나타난다(small scope hypothesis).

값을 하나라도 무제한으로 늘릴 수 있는 액션이 있으면(잔액을 계속 올리는 `charge`) 상태공간은 무한하고, 좁히지 않으면 탐색은 **끝나지 않는다.** 좁히는 축은 셋이고 서로 독립이다. 쓴 축과 그 값을 보고에 적는다.

| 축 | 무엇을 자르나 | 예 |
|---|---|---|
| **값 집합** | 각 필드가 가질 수 있는 값 | 금액 `{0, 1, MAX}`, 사용자·주문 2개, 틱 3~5개 |
| **값 창** | 상태의 절댓값 한계 | `abs(balance) <= W` 를 넘는 상태는 큐에 안 넣는다 |
| **깊이** | 명령열 길이 | 초기 상태부터 6수 이내 |

`MAX` 는 **불변식이 구별하는 경계를 넘는 값**이다. `{0, 1}` 만 쓰면 "1을 보류하고 2를 확정" 같은 초과 반례를 만들 수 없다 — 초과가 불변식의 관심사면 `MAX` 는 2 이상이어야 한다.

값 집합만으로 유한해지면 나머지 둘은 쓰지 않는다. 세 축을 다 써도 프론티어가 안 비면 모델이 질문에 비해 크다는 뜻이니 Phase 3 첫 문단으로 돌아간다.

도달성 전수 탐색의 뼈대:

```
frontier = [(초기상태, [])]
seen     = { key(초기상태) }
while frontier:                          # 좁힌 범위 안에서는 반드시 빈다
    s, path = frontier.pop(0)
    for a in actions(s):                 # 설계가 적어 둔 전제조건만 반영
        n, npath = reduce(s, a), path + [a]
        for inv in INVARIANTS:
            if not inv.holds(n): 반례 기록 (inv, npath, n)
        if key(n) in seen:      continue
        if 범위_밖(n) or len(npath) > 깊이: 잘림 기록; continue
        seen.add(key(n))
        frontier.append((n, npath))
```

`범위_밖` 과 깊이 검사가 **좁힌 범위를 코드로 옮긴 자리**다. 여기서 자른 상태를 세어 보고에 적는다 — 잘림이 0이면 그 축은 실제로 걸리지 않았다는 뜻이고, 축을 아예 안 썼는지 썼는데 안 걸렸는지가 그 숫자로 갈린다.

`key()` 는 정규화된 직렬화다 — 순서가 안정적이어야 같은 상태를 두 번 세지 않는다. 명령열을 상태와 함께 들고 다니는 이유는 Phase 4 가 반례에 경로를 요구하기 때문이다.

### 완료 기준 — 좁힌 범위 안에서 프론티어가 비었다

**전수는 언제나 "좁힌 범위 안에서의 전수"다.** 범위를 밝히지 않은 "안 깨졌다"는 아무 뜻이 없다.

- [ ] `frontier` 가 비어 탐색이 끝났다
- [ ] 쓴 축과 값, 그리고 각 축이 잘라 낸 상태 수가 보고에 적혀 있다 — **축을 하나도 안 썼으면 "없음, 잘림 0" 이 그 답이고 통과다**
- [ ] 범위를 **한 축만 한 단계 넓혀** 다시 돌려도 최단 반례의 길이가 그대로다

셋째가 범위가 결론을 만들고 있지 않다는 확인이다. **한 축만** 넓히는 이유는 여럿을 같이 넓히면 어느 축이 결론을 쥐고 있었는지 못 가리기 때문이다. 축을 하나도 안 썼으면 설계가 고정한 값 집합을 하나 넓힌다(좌석 3개 → 4개). 넓혔더니 없던 반례가 나오면 이전 범위가 너무 좁았던 것이니 넓힌 쪽을 보고한다.

프론티어가 안 빈 채 멈춘 탐색은 전수가 아니라 **표본**이다. 표본은 반례를 찾으면 확실하고, 못 찾으면 아무것도 뜻하지 않는다. 그대로 보고하려면 "표본, 반례 없음"이라 적고 **"안전하다"고 쓰지 않는다.**

## Phase 4 — 반례를 낸다

보고는 네 갈래다. 가운데 둘은 테스트로는 나오지 않는다 — 테스트는 있는 것만 확인하지, 없어야 할 것과 없는 것을 못 짚는다.

| 갈래 | 뜻하는 것 |
|---|---|
| **불변식 위반** | 설계 결함. 본체 |
| **도달 불가능** | 선언했는데 어떤 명령열로도 못 감 → 모델 **과잉** (이름 붙은 상태가 없는 모델이면 "선언" 은 **필드 타입이 허용하는 값 조합**이다) |
| **표현 불가능** | 도메인에선 일어나는데 모델로 못 그림 → 모델 **부족** |
| **의외인 도달 가능 상태** | 불변식은 안 깨졌는데 예상 밖 → 불변식의 빈틈 |

**반례는 초기 상태부터의 명령열 원문 그대로 낸다.** 요약하면 사람이 판정할 재료가 사라진다. 판정은 사용자가 한다 — 반례를 제시하고 **불변식이 너무 강한 것인지 설계가 틀린 것인지** 묻는다.

### 완료 기준

- [ ] 네 갈래가 모두 채워졌다 (해당 없으면 "없음")
- [ ] 각 반례에 초기 상태부터의 전체 명령열이 붙어 있다
- [ ] 검증된 것은 모델이지 구현이 아니라는 한계가 보고에 적혀 있다

## Phase 5 — 판정을 남긴다

남길 것은 셋이다.

- **결정** — 모델을 고쳤거나 대안 중 이것을 골랐다면 그 이유.
- **용어** — 불변식을 문장으로 쓰다 드러난 모호함. 이 단계에서 가장 잘 걸린다.
- **리듀서** — 검증된 모델은 실코드로 올린다. 탐색 하네스는 버린다.

**어디에** 남길지는 계단을 내려간다. 위에서 맞는 것이 나오면 거기서 멈춘다.

1. **그 종류의 기록을 두는 자리가 저장소에 있으면 거기에.** ADR 디렉토리, 용어집, 이슈 트래커. 기존 문서의 형식을 그대로 따른다 (`/domain-modeling` 을 쓰는 저장소면 ADR-FORMAT).
2. **없으면 검사 대상 설계 문서에 절을 추가한다.** 그것이 그 저장소의 유일한 설계 기록이면 거기가 이미 쓰는 자리다.
3. **설계 문서조차 없으면 사용자에게 묻는다.**

**금지되는 것은 새 파일·새 디렉토리를 만드는 것뿐이다.** 있는 문서에 절을 붙이는 것은 새로 만드는 것이 아니다.

반례를 회귀 테스트로 얼릴 때 기대값은 **사용자가 판정한 값**을 쓴다(`/tdd`). 탐색기가 계산한 값을 기대값으로 쓰면 그 테스트는 코드가 아니라 탐색기와 자기 자신을 검증한다.

### 완료 기준

- [ ] 판정된 반례마다 처리가 정해졌다 (모델 수정 / 불변식 수정 / 의도된 동작)
- [ ] 결정과 용어를 각각 어디에 남겼는지, 또는 남기지 않기로 한 이유가 적혀 있다

### 나가는 문은 둘이다

Phase 4 가 판정을 사용자에게 넘기므로, **사용자가 아직 답하지 않은 채 Phase 5 에 서 있는 것이 정상 상태다.** 어느 문으로 나가는지 보고 첫 줄에 적는다.

1. **남김** — 판정이 정해졌고 세 산출물이 각자의 자리로 갔다. 리듀서는 **검증을 통과한 모델만** 올린다 — 반례가 남아 있으면 그 모델은 검사 대상이지 승격 대상이 아니다.
2. **판정 대기** — 사용자 답을 못 받아 멈췄다. 미결 질문을 **목록으로** 남기고 넘긴다. Phase 1 의 문 3 과 같은 형식이다.

   완료 기준은 **실제로 한 만큼** 판정한다. 판정을 못 받았으면 첫 박스가 미충족이고, 판정은 받았는데 자리만 못 정했으면(계단 3단) 첫 박스는 충족이고 둘째가 미충족이다. 다만 **판정된 반례가 0 개인 것을 "판정된 반례마다" 의 공허참으로 읽어 통과시키지 않는다.**
