# 탐색 기법

[`SKILL.md`](../SKILL.md) Phase 2 에서 고른 기법의 절만 읽는다.

각 절은 **언제 / 하네스 / 함정** 순이다. 기법을 추가할 때도 이 세 항목을 채우고 `SKILL.md` 의 표에 한 줄을 더한다.

---

## 1. 왕복 (round-trip)

**언제** — 직렬화, 저장/복원, 인코딩/디코딩, 파싱/렌더링. 값을 바꿔 내보냈다가 되읽는 모든 경계.

**하네스** — 값 생성기 하나와 `decode(encode(x)) == x` 한 줄. 생성기는 도메인 타입을 무작위로 만들되 경계값(빈 값, 최대 길이, 유니코드, 음수, 0)을 반드시 섞는다.

**함정** — 동등 비교가 진짜 동등이어야 한다. 부동소수, 맵 순서, 타임존, 후행 공백에서 거짓 반례가 쏟아진다. 정규화 함수를 먼저 만들고 그 위에서 비교한다. 정규화가 버그를 가리기 시작하면 정규화를 좁힌다.

---

## 2. 도달성 전수 탐색 (BFS)

**언제** — 상태기계, 승인/결재 워크플로, 권한 판정, 예약·재고. 액션이 이산적이고 열거 가능할 때.

**하네스** — `SKILL.md` Phase 3 의 뼈대. `actions(s)` 는 **설계가 적어 둔 전제조건만** 반영한다. 조건을 무시하고 전부 돌려준 뒤 `reduce` 안에서 걸러내면 도달 불가능 상태 판정이 망가진다.

**설계가 전제조건을 안 적은 액션은 모든 상태에서 합법으로 둔다.** 빠진 가드가 바로 검사 대상인 경우가 많다 — 상상해서 채워 넣는 순간 그 가드가 막았을 반례가 통째로 사라져, 찾으려던 결함이 하네스에 숨는다. 가드가 필요하다는 판단이 들면 하네스에 넣지 말고 **반례로 내라.** "이 명령열이 도달하는 상태를 막으려면 여기 가드가 필요하다"가 사용자가 받아야 할 판정이다.

**함정** — `key()` 가 상태를 과소 구별하면 탐색이 조기 종료하고 "전수 완료"라 거짓 보고한다. 배열 순서·집합·부동소수를 key 에 넣기 전에 정렬·양자화한다. 반대로 과다 구별하면(타임스탬프, UUID) 상태공간이 폭발한다 — 그런 필드는 모델에서 뺀다.

---

## 3. 차등 실행 (differential)

**언제** — 리팩토링, 마이그레이션, 재작성, 캐시 도입. **기존 구현이 오라클 노릇을 하므로 도메인 지식이 필요 없다.**

**하네스** — 같은 입력을 옛 구현과 새 구현에 넣고 출력을 비교한다. 입력은 무작위 생성이거나 실제 로그 리플레이.

**함정** — 옛 구현의 버그까지 정답으로 굳는다. 차이가 나온 지점마다 "새 쪽이 틀린 것인가, 옛 쪽 버그를 고친 것인가"를 사용자에게 묻는다 — 자동으로 옛 쪽 편을 들지 않는다. 의도된 동작 변경은 목록으로 먼저 받아 두고 그것만 예외 처리한다.

---

## 4. 순서 교환 (commutativity)

**언제** — "이 두 명령의 순서가 결과를 바꾸나". 이벤트 재정렬, 배치 처리, 오프라인 동기화.

**하네스** — 명령열을 만들고, 인접한 두 명령을 뒤집은 변형을 함께 실행해 최종 상태를 비교한다. 전수 탐색(2번)이 이미 돌고 있으면 그 경로 집합에서 순열을 뽑아 쓴다.

**함정** — 순서가 결과를 바꾸는 것이 **정상인** 명령 쌍이 대부분이다. 교환 가능해야 하는 쌍을 Phase 1 에서 불변식으로 미리 지목받는다. 지목 없이 전부 비교하면 거짓 반례에 파묻힌다.

---

## 5. 인터리빙 (interleaving)

**언제** — 동시 실행, 경쟁 조건, 락 설계, 낙관적 잠금.

**하네스** — 각 트랜잭션을 원자적 단계 열로 쪼개고, 두 열의 가능한 인터리빙을 전부 열거해 각 결과에 불변식을 건다. 실제 스레드를 쓰지 않는다 — 스케줄을 값으로 열거해야 재현된다.

**함정** — 단계를 굵게 쪼개면 진짜 경쟁을 못 잡고, 잘게 쪼개면 폭발한다. 공유 상태를 읽고 쓰는 지점에서만 자른다. 트랜잭션 2개 × 단계 4개면 인터리빙 70개 — 3개로 늘리기 전에 2개에서 아무것도 안 나오는지부터 확인한다.

---

## 6. 변형 관계 (metamorphic)

**언제** — 정답을 모르지만 **입력을 바꿨을 때 출력이 어떻게 변해야 하는지**는 아는 경우. 검색 랭킹, 추천, 요약, 집계.

**하네스** — 관계를 코드로 적는다. `f(sorted(x)) == sorted(f(x))`, `f(x + [무관한 항목])` 이 상위 결과를 바꾸지 않음, 통화 단위를 바꿔도 순위가 같음.

**함정** — 관계가 실제로는 성립하지 않는데 그럴듯해서 채택되기 쉽다. 각 관계마다 Phase 1 의 출처 넷 중 하나를 지목한다 — "말이 되니까"는 출처가 아니다.

---

## 7. 무작위 + 축소 (property-based)

**언제** — 값 범위가 넓어 전수가 불가능할 때. 수치 계산, 문자열 처리, 넓은 입력 도메인.

**하네스** — 프로젝트 언어의 라이브러리를 쓴다(Hypothesis, fast-check, jqwik). **축소(shrink)가 이 기법의 값어치다** — 실패를 최소 반례로 줄여 주지 않으면 사람이 판정할 수 없다. 직접 구현하지 말고 라이브러리의 축소를 쓴다.

**함정** — 이건 **표본**이지 전수가 아니다. 보고 규칙은 `SKILL.md` Phase 3 완료 기준의 표본 문단을 그대로 따른다. 라이브러리가 실패 예제를 저장한다면(Hypothesis 의 example DB, Go 의 `testdata/fuzz/`) 그 파일을 저장소에 커밋한다.

---

## 8. 결함 주입 (fault injection)

**언제** — 재시도, 타임아웃, 부분 실패, 중복 전달, 순서 뒤바뀜이 얽힌 흐름.

**하네스** — 실패를 액션으로 모델에 넣는다 — `[타임아웃]`, `[중복전달]`, `[응답유실]` 을 정상 액션과 같은 자리에 두면 2번의 전수 탐색이 그대로 결함 조합을 훑는다. 시간은 실제 시계가 아니라 **논리 시계 틱**으로 둔다.

**함정** — 실패 액션을 넣으면 상태공간이 배로 뛴다. 결함 종류를 한 번에 하나씩 켜고, 그것만으로 반례가 나오면 거기서 멈춘다. 전부 켜고 시작하면 폭발한 뒤 어느 결함이 원인인지 못 가린다.
