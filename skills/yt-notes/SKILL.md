# 유튜브 영상 원문 저장 · 정리 · 이야기

한 번 실행에 영상 하나를 다룬다.

`<스킬>` 은 이 `SKILL.md` 가 있는 디렉토리의 절대 경로다. 저장 위치는 `$YT_NOTES_HOME`, 없으면 `~/video-notes/`. 영상 하나가 `<slug>/transcript.md`(원문)와 `<slug>/notes.md`(정리)이고, `transcript.md` 는 스크립트만 쓴다.

## 1. 입구를 가른다

- **URL** — `uv run <스킬>/scripts/yt_notes.py info <url>`. `existing` 이 `null` 이면 2단계, 아니면 그 `status` 로 간다.
- **인자 없음** — `uv run <스킬>/scripts/yt_notes.py list` 로 목록을 보여주고 하나 고르게 한다.
- **slug** — 그 디렉토리의 `notes.md` frontmatter 를 읽는다.

`status` 가 `transcribed` 면 3단계, `discussing` 이면 4단계(남은 주제부터), `done` 이면 5단계의 재진입이다.

**완료 기준**: 어느 단계로 갈지 정해졌다. URL 이면 `info` 출력이 손에 있다.

## 2. 원문을 저장한다

slug 를 짓는다. 제목의 **뜻**을 영문 kebab 3~5 단어로 옮긴다 — 한국어 제목을 음역하지 않는다. 채널 이름, "영상", "강연", "완전정복" 같은 군말은 뺀다. 예: "AI 시대, 기업은 어떤 인재를 뽑을까? | 조코딩" → `ai-era-hiring`. 충돌은 스크립트가 유튜브 ID 앞 4자를 붙여 푼다.

```
uv run <스킬>/scripts/yt_notes.py save <url> <slug>
```

실행 전에 `info` 의 `plan` 과 `estimate_seconds` 를 한 줄로 말한다. 첫 실행이면 CUDA 라이브러리와 모델 3GB 를 uv 캐시로 받느라 몇 분 더 걸린다고 덧붙인다. 예상이 1분을 넘으면 `run_in_background` 로 돌리고 끝나면 이어 간다.

플래그 둘. `--captions` 는 GPU 가 있어도 자막을 먼저 쓴다(빠른 초안이 필요할 때). `--whisper` 는 자막을 무시하고 전사하며, 이미 저장된 영상에 주면 `transcript.md` 만 갈아 끼우고 `notes.md` 는 그대로 둔다.

출력의 제목·채널·길이·`source`(whisper 면 `model` 도)·줄 수를 보여준다. **어느 출처든 오인식이 섞인다**고 한 줄 덧붙인다 — 이야기 중 이상한 단어는 원문 오류일 수 있다. `source: auto`(자동자막)면 더 그렇다: 글자 오류율 실측이 자동자막 0.31, whisper small 0.22, large-v3-turbo 0.15~0.20 이다(한국어 기술 강연 3개). whisper 는 영문 용어를 한글로 적는 쪽으로 틀린다.

그리고 **"지금 정리로 들어갈까?" 한 줄 묻고 멈춘다.** 들어간다고 하면 3단계 — 저장은 몇 초, 정리와 이야기는 몇십 분이라 같은 자리에서 끝나지 않는다.

**완료 기준**: `<home>/<slug>/transcript.md` 와 `notes.md` 가 있고, 사용자가 제목·길이·원문 출처를 받았다.

## 3. 핵심과 흐름을 정리한다

[`references/notes-format.md`](references/notes-format.md) 를 읽는다. `transcript.md` 를 **끝까지** 읽는다 — 3시간짜리도 통째로. 앞부분만 읽고 쓴 핵심은 영상의 결론을 놓친다.

`notes.md` 에 셋을 쓴다.

- **`## 핵심`** — 영상이 하는 주장 3~5줄, 줄마다 `[mm:ss]`(1시간을 넘는 영상은 `[h:mm:ss]`). 고르는 기준은 셋이다: 영상이 시간을 가장 많이 쓴 것, 되풀이한 것, 다른 주장의 전제가 되는 것. 날짜·이름·수치 나열은 핵심이 아니다.
- **`## 흐름`** — 영상을 3~5구간으로 나누고, 구간마다 제목과 `[mm:ss-mm:ss]`, 요약 2~4줄(줄 끝에 `[mm:ss]`). `transcript.md` frontmatter 의 `chapters`(유튜브 챕터)는 재료지 구간이 아니다 — 3분 영상에 9개, 20분에 10개라 그대로 쓰면 잘다(실측). 제목이 화제 전환을 알려 주니 묶어서 쓰고, 없으면 원문에서 화제가 바뀌는 곳으로 나눈다.
- **`## 이야기`** — 이야기 나눌 주제 3~6개, 흐름 순. 주제마다 `영상:`(원문 인용, `[mm:ss]`)과 `왜 여기:` 를 채운다. 고르는 기준은 넷이다.
  - **핵심** — 위의 핵심 그 자체.
  - **구멍** — 영상이 주장은 하고 이유는 안 대는 데. 실사용에서 "다음 단계를 감추면 왜 앞 단계에 힘이 실리나"가 원문에 없었고, 저자의 현행 문서에서 답을 찾았다.
  - **틀린 데** — 낡았거나 틀린 것 같은 데. `upload_date` 를 본다 — 영상이 최신이고 네 지식이 낡았을 수 있다.
  - **닿는 데** — 사용자의 일과 닿는 데. 세션 맥락과 현재 저장소에서 보이는 것으로 잡는다.

frontmatter 를 `status: discussing` 으로 바꾸고 `discussed` 에 오늘 날짜를 더한다. 사용자에게 **`## 핵심` 과 `## 흐름` 을 파일에 쓴 그대로**, 그 아래 이야기 주제 목록(제목과 `왜 여기`)을 보여주고, 어디부터 할지 묻고 멈춘다.

**완료 기준**: `## 핵심` 이 3~5줄이고, `## 흐름` 마지막 구간의 끝 시각이 frontmatter 의 `duration`(초)에 닿는다 — 끝까지 읽었다는 표다. `## 이야기` 의 주제마다 `왜 여기` 가 네 기준 중 하나를 대고, 사용자가 핵심·흐름·주제 목록을 받았다.

## 4. 이야기한다

**한 턴에 주제 하나를 열고 멈춘다.** 다음 턴은 사용자의 답으로 시작한다 — 답을 대신 써서 이으면 정리가 사용자 것이 아니게 된다.

주제를 열 때는 영상의 말을 `[mm:ss]` 와 함께 짚고, `왜 여기` 를 그대로 말한다 — 구멍이면 어디가 비었는지, 틀린 데면 무엇이 의심되는지, 닿는 데면 사용자의 무엇과 닿는지. 그리고 사용자 쪽으로 묻는다: 네 일에서는 이게 어떻게 되나, 어디가 걸리나.

답이 오면 다음 말을 보내기 **전에** 셋을 한다.

1. **기록한다.** 답을 그 주제의 `네 말:` 에 그대로 옮긴다 — 사용자가 쓴 낱말과 문장 길이를 그대로 두고 군말과 반복만 덜어낸다. 비워 두는 것이 지어내는 것보다 낫다. 먼저 하는 이유는 세션이 끊기거나 컨텍스트가 요약돼도 사용자의 말이 디스크에 남게 하기 위해서다.
2. **채운다.**
   - 사용자가 모르겠다고 하거나 구멍이면, 먼저 원문에서 찾아 `[mm:ss]` 로 보여준다. 원문이 답하지 않으면 밖에서 찾는다 — 저자의 현행 문서, 공식 문서, 원 논문 순. 찾은 것은 요지 몇 줄과 출처로 주고 `더 찾은 것:` 에 적는다. 리서치는 지금 물음 하나에 답하고 돌아온다 — 주제마다 웹을 뒤지면 이야기가 안 끝난다.
   - 영상이 틀렸으면 근거를 들고 정정하고 `정정:` 에 적는다. **정정에는 출처가 붙는다.** 출처를 못 찾으면 의심으로 두고 `## open_questions` 에 적는다.
   - 사용자의 이해가 원문과 갈리면 그 자리에서 `[mm:ss]` 와 함께 짚고 `걸린 점:` 에 적는다. 실사용에서 사용자가 no-op 의 방향을 거꾸로 읽은 채 끝날 뻔했다.
3. **잇는다.** 채운 뒤에는 사용자 쪽으로 되묻는 한 줄을 붙인다 — 완성해서 주면 사용자는 읽기만 한다. 주제가 닫혔으면 다음 주제로.

사용자가 끊으면 — "여기까지", "그만", "다음에" — 남은 주제를 `## open_questions` 에 적고 5단계로 간다.

**완료 기준**: `## 이야기` 의 주제마다 `네 말` 이 있거나 그 번호가 `## open_questions` 에 있다. `정정` 마다 출처가 있다.

## 5. 정리한다

`## 정리` 를 `notes.md` 맨 위에 쓴다. 5~10줄. 재료는 `네 말`·`걸린 점`·`더 찾은 것`·`정정` 이다 — 영상 요약이 아니라 **우리가 나눈 이야기**를 적는다: 사용자가 어디에 닿았고, 무엇이 고쳐졌고, 무엇이 더해졌는지. 사용자가 쓴 낱말을 그대로 쓴다 — 네 표현으로 바꾸면 나중에 다시 읽을 때 사용자 글이 아니다. 정정과 리서치 줄에는 출처를 붙인다.

`notes.md` 의 **구조만** 다듬는다 — 순서, 중복, 빈 칸. 사용자의 표현은 그대로 둔다. frontmatter 를 `status: done` 으로 바꾸고, `## 정리` 와 `open_questions` 를 읽어준다.

**재진입** — `done` 인 영상을 다시 부르면 이어서 이야기할지 묻는다. 한다면 `status: discussing` 으로 돌리고 `open_questions` 부터 시작한다. 새 주제는 `## 이야기` 끝에 더한다. 이전 `네 말` 은 지우지 않고 그 아래에 날짜를 붙여 덧붙인다.

**완료 기준**: `status` 가 `done` 이고, `## 정리` 가 맨 위에 있고 줄마다 근거가 `## 이야기` 에 있고, 사용자가 `## 정리` 와 `open_questions` 를 받았다.
