# 유튜브 영상 원문 저장 · 토의 · 정리

한 번 실행에 영상 하나를 다룬다. 원문 저장에서 멈추고, 토의는 따로 시작한다 — 저장은 몇 초, 토의는 몇십 분이라 같은 자리에서 끝나지 않는다.

`<스킬>` 은 이 `SKILL.md` 가 있는 디렉토리의 절대 경로다. 저장 위치는 `$YT_GRILL_HOME`, 없으면 `~/video-notes/`. 영상 하나가 `<slug>/transcript.md`(원문)와 `<slug>/notes.md`(정리)다. 형식은 [`references/layout.md`](references/layout.md).

스크립트는 `uv run` 으로 돈다. 설치는 없고 첫 실행에 uv 캐시로 패키지를 받는다.

## 1. 입구를 가른다

인자가 무엇이냐로 갈린다.

- **URL** — `uv run <스킬>/scripts/yt_grill.py info <url>`. 출력의 `existing` 이 `null` 이면 2단계. 아니면 `status` 로 간다: `transcribed` → 3단계, `discussing` → 4단계(남은 주장부터), `done` → 5단계의 재진입.
- **인자 없음** — `uv run <스킬>/scripts/yt_grill.py list` 로 목록을 보여주고 하나 고르게 한다. 고른 영상의 `status` 로 위와 같이 간다.
- **slug** — 그 디렉토리의 `notes.md` frontmatter 를 읽고 `status` 로 간다.

**완료 기준**: 어느 단계로 갈지 정해졌다. URL 이면 `info` 출력이 손에 있다.

## 2. 원문을 저장한다

slug 를 짓는다. 제목의 **뜻**을 영문 kebab 3~5 단어로 옮긴다 — 한국어 제목을 음역하지 않는다. 채널 이름, "영상", "강연", "완전정복" 같은 군말은 뺀다. 예: "AI 시대, 기업은 어떤 인재를 뽑을까? | 조코딩" → `ai-era-hiring`. 충돌은 스크립트가 유튜브 ID 앞 4자를 붙여 푼다.

```
uv run <스킬>/scripts/yt_grill.py save <url> <slug>
```

`info` 의 `pick` 이 `null` 이면 자막이 없고, `save` 가 로컬 whisper 로 넘어간다. 과금은 없지만 CPU 로 1시간 영상에 7~8분이 든다(실측). 그 사실을 먼저 말하고 `run_in_background` 로 돌린 뒤 끝나면 이어 간다. 첫 실행은 모델 파일 약 460MB 를 더 받는다.

출력의 제목·채널·길이·자막 출처(`source`)·줄 수를 보여준다. `source` 가 `auto` 나 `whisper` 면 오인식이 섞여 있다고 한 줄 덧붙인다 — 토의 중 이상한 단어는 원문 오류일 수 있다.

자동자막이 기술 용어를 심하게 깨뜨리면(실측: "리액트 쿼리 캐시"가 "리 캐시") `save <url> <slug> --whisper` 로 원문만 다시 받을 수 있다. 이미 저장된 영상이면 `transcript.md` 만 갈아 끼우고 `notes.md` 는 그대로 둔다. whisper 는 용어가 조금 낫고 문장 단위라 읽기 좋지만, 28분에 5분쯤 든다 — 사용자가 원할 때만.

그리고 **"지금 토의로 들어갈까?" 한 줄 묻고 멈춘다.** 들어간다고 하면 3단계.

**완료 기준**: `<home>/<slug>/transcript.md` 와 `notes.md` 가 있고, 사용자가 제목·길이·자막 출처를 받았다.

## 3. 뼈대를 세운다

[`references/layout.md`](references/layout.md) 를 읽는다. `transcript.md` 를 **끝까지** 읽는다 — 3시간짜리도 통째로. 앞부분만 읽고 뽑은 주장은 영상의 결론을 놓친다.

`notes.md` 에 쓴다:

- `## 요약` — 5~10줄, 영상이 말한 순서대로, 각 줄 끝에 `[mm:ss]`.
- `## 핵심 주장` — 3~5개. 10분 이하는 3개, 1시간 이상은 5개쯤. 고르는 기준은 셋이다: 영상이 시간을 가장 많이 쓴 것, 영상이 되풀이한 것, 다른 주장의 전제가 되는 것. 날짜·이름·수치 나열은 주장이 아니다. 주장마다 `영상의 말`(원문 인용, `[mm:ss]`)을 채우고 `네 말`·`걸린 점` 은 비워 두며 `판정: 미도달 (0회)` 로 시작한다.
- frontmatter — `status: discussing`, `discussed` 에 오늘 날짜를 더한다.

사용자에게 요약과 주장 목록을 보여주고, 바로 4단계의 첫 질문으로 들어간다.

**완료 기준**: `notes.md` 에 요약, 주장 목록, 주장마다 판정 칸이 있고 `status` 가 `discussing` 이다.

## 4. 토의한다

**한 턴에 질문 하나를 보내고 멈춘다.** 답은 사용자가 쓴다. 답을 가정하고 다음 질문까지 이어 쓰지 않는다 — 지어낸 답이 한 줄이라도 섞이면 정리 전체가 사용자 것이 아니게 된다.

주장 1부터 순서대로 간다. 첫 질문은 "이 주장을 네 말로 하면?" 계열이다. 원문 대목을 짚을 때는 `[mm:ss]` 와 함께 인용한다.

답이 오면 다음 질문을 보내기 **전에** 세 가지를 한다.

1. **기록한다.** 답을 그 주장의 `네 말:` 에 그대로 옮긴다 — 군말과 반복만 덜어낸다. 걸린 점이 보이면 `걸린 점:` 에. 이걸 먼저 하는 이유는 세션이 끊기거나 컨텍스트가 요약돼도 사용자의 말이 디스크에 남게 하기 위해서다.
2. **판정한다.** `판정:` 에 도달/미도달과 회수를 적는다. 사용자가 주장을 제 말로 설명했으면 도달이다. 도달·미도달의 세부 정의는 두지 않는다 — 있어도 판정이 안 갈리고, 있으면 판정을 입 밖에 내는 판이 생겼다([`README.md`](README.md)).

   판정은 머릿속에서만 한다. "그건 영상 말 그대로네요" 라고 하는 순간 사용자가 말을 고르기 시작한다.
3. **다음 질문을 정한다.** 도달이면 다음 주장으로. 미도달이면 각도를 바꿔 같은 주장을 다시 묻는다 — 자기 경험에서 예를 요구한다 → 이 주장이 틀리는 경우를 묻는다 → 원문 대목을 `[mm:ss]` 와 함께 보여주고 거기서 무엇이 걸리는지 묻는다. **3회 미도달이면** `## open_questions` 에 "주장 N — 3회 미도달, 쓴 각도: …" 를 적고 다음 주장으로 넘어간다.

사용자가 질문을 던지면 원문을 근거로 답하고(`[mm:ss]` 인용), 해당 주장 아래 또는 `## 내 질문` 에 질문과 답의 요지를 적은 뒤 하던 주장으로 돌아간다.

사용자가 끊으면 — "여기까지", "그만", "다음에" — 남은 주장을 `## open_questions` 에 적고 5단계로 간다.

**완료 기준**: 모든 주장이 도달이거나 `open_questions` 에 있다. 끊었으면 남은 주장이 전부 `open_questions` 에 있다.

## 5. 마무리한다

`notes.md` 의 **구조만** 다듬는다 — 순서, 중복, 빈 칸. 사용자의 표현은 바꾸지 않는다. frontmatter 를 `status: done` 으로 바꾼다.

`open_questions` 를 읽어준다. 커버리지 숫자("5개 중 3개")는 읽어주지 않는다 — 할당량으로 들린다.

**재진입** — `done` 인 영상을 다시 부르면 다시 토의할지 묻는다. 한다면 `status: discussing` 으로 돌리고 `open_questions` 의 주장부터 시작한다. 새로 뽑을 주장이 있으면 목록 끝에 더한다. 이전 `네 말` 은 지우지 않고 그 아래에 날짜를 붙여 덧붙인다.

**완료 기준**: `status` 가 `done` 이고 사용자가 `open_questions` 를 안다.
