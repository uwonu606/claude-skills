# 유튜브 영상 원문 저장 · 토의 · 정리

한 번 실행에 영상 하나를 다룬다.

`<스킬>` 은 이 `SKILL.md` 가 있는 디렉토리의 절대 경로다. 저장 위치는 `$YT_GRILL_HOME`, 없으면 `~/video-notes/`. 영상 하나가 `<slug>/transcript.md`(원문)와 `<slug>/notes.md`(정리)이고, `transcript.md` 는 스크립트만 쓴다.

## 1. 입구를 가른다

- **URL** — `uv run <스킬>/scripts/yt_grill.py info <url>`. `existing` 이 `null` 이면 2단계, 아니면 그 `status` 로 간다.
- **인자 없음** — `uv run <스킬>/scripts/yt_grill.py list` 로 목록을 보여주고 하나 고르게 한다.
- **slug** — 그 디렉토리의 `notes.md` frontmatter 를 읽는다.

`status` 가 `transcribed` 면 3단계, `discussing` 이면 4단계(남은 주장부터), `done` 이면 5단계의 재진입이다.

**완료 기준**: 어느 단계로 갈지 정해졌다. URL 이면 `info` 출력이 손에 있다.

## 2. 원문을 저장한다

slug 를 짓는다. 제목의 **뜻**을 영문 kebab 3~5 단어로 옮긴다 — 한국어 제목을 음역하지 않는다. 채널 이름, "영상", "강연", "완전정복" 같은 군말은 뺀다. 예: "AI 시대, 기업은 어떤 인재를 뽑을까? | 조코딩" → `ai-era-hiring`. 충돌은 스크립트가 유튜브 ID 앞 4자를 붙여 푼다.

```
uv run <스킬>/scripts/yt_grill.py save <url> <slug>
```

실행 전에 `info` 의 `plan` 과 `estimate_seconds` 를 한 줄로 말한다. 첫 실행이면 CUDA 라이브러리와 모델 3GB 를 uv 캐시로 받느라 몇 분 더 걸린다고 덧붙인다. 예상이 1분을 넘으면 `run_in_background` 로 돌리고 끝나면 이어 간다.

플래그 둘. `--captions` 는 GPU 가 있어도 자막을 먼저 쓴다(빠른 초안이 필요할 때). `--whisper` 는 자막을 무시하고 전사하며, 이미 저장된 영상에 주면 `transcript.md` 만 갈아 끼우고 `notes.md` 는 그대로 둔다.

출력의 제목·채널·길이·`source`(whisper 면 `model` 도)·줄 수를 보여준다. **어느 출처든 오인식이 섞인다**고 한 줄 덧붙인다 — 토의 중 이상한 단어는 원문 오류일 수 있다. `source: auto`(자동자막)면 더 그렇다: 글자 오류율 실측이 자동자막 0.31, whisper small 0.22, large-v3-turbo 0.15~0.20 이다(한국어 기술 강연 3개). whisper 는 영문 용어를 한글로 적는 쪽으로 틀린다.

그리고 **"지금 토의로 들어갈까?" 한 줄 묻고 멈춘다.** 들어간다고 하면 3단계 — 저장은 몇 초, 토의는 몇십 분이라 같은 자리에서 끝나지 않는다.

**완료 기준**: `<home>/<slug>/transcript.md` 와 `notes.md` 가 있고, 사용자가 제목·길이·원문 출처를 받았다.

## 3. 챕터로 뼈대를 세운다

[`references/notes-format.md`](references/notes-format.md) 를 읽는다. `transcript.md` 를 **끝까지** 읽는다 — 3시간짜리도 통째로. 앞부분만 읽고 뽑은 주장은 영상의 결론을 놓친다.

**챕터가 토의의 단위다.** 3~5개로 나눈다. `transcript.md` frontmatter 의 `chapters`(유튜브 챕터)는 재료지 단위가 아니다 — 3분 영상에 9개, 20분에 10개라 그대로 쓰면 잘다(실측). 제목이 화제 전환을 알려 주니 묶어서 쓰고, 없으면 원문에서 화제가 바뀌는 곳으로 나눈다.

챕터마다 `notes.md` 에 쓴다:

- 챕터 제목과 구간 `[mm:ss-mm:ss]`(1시간을 넘는 영상은 `[h:mm:ss]`), 그 아래 요약 2~4줄(각 줄 끝에 `[mm:ss]`).
- 주장 1~2개, 영상 전체로 3~5개. 고르는 기준은 셋이다: 영상이 시간을 가장 많이 쓴 것, 영상이 되풀이한 것, 다른 주장의 전제가 되는 것. 날짜·이름·수치 나열은 주장이 아니다.
- 주장마다 `영상의 말`(원문 인용, `[mm:ss]`)을 채우고 `네 말`·`걸린 점` 은 비워 두며 `판정: 미도달 (0회)` 로 시작한다.

frontmatter 를 `status: discussing` 으로 바꾸고 `discussed` 에 오늘 날짜를 더한다. 사용자에게는 **챕터 목록과 첫 챕터 요약만** 보여주고 4단계로 간다 — 전체를 미리 펼치면 토의 전에 답을 읽는다.

**완료 기준**: 챕터가 3~5개이고 **마지막 챕터의 끝 시각이 frontmatter 의 `duration`(초) 에 닿는다** — 끝까지 읽었다는 표다. 챕터마다 요약과 주장이 있고 `status` 가 `discussing` 이다.

## 4. 챕터를 토의한다

**한 턴에 질문 하나를 보내고 멈춘다.** 답은 사용자가 쓴다. 답을 가정하고 다음 질문까지 이어 쓰지 않는다 — 지어낸 답이 한 줄이라도 섞이면 정리 전체가 사용자 것이 아니게 된다.

챕터 1의 주장 1부터 순서대로 간다. 첫 질문은 "이 주장을 네 말로 하면?" 계열이다. 원문 대목을 짚을 때는 `[mm:ss]` 와 함께 인용한다.

답이 오면 다음 질문을 보내기 **전에** 세 가지를 한다.

1. **기록한다.** 답을 그 주장의 `네 말:` 에 그대로 옮긴다 — 사용자가 쓴 낱말과 문장 길이를 그대로 두고 군말과 반복만 덜어낸다. **비워 두는 것이 지어내는 것보다 항상 낫다.** 걸린 점이 보이면 `걸린 점:` 에. 이걸 먼저 하는 이유는 세션이 끊기거나 컨텍스트가 요약돼도 사용자의 말이 디스크에 남게 하기 위해서다.
2. **판정한다.** `판정:` 에 도달/미도달과 회수를 적는다. 사용자가 주장을 제 말로 설명했으면 도달이다.

   **판정은 비공개다.** "그건 영상 말 그대로네요" 라고 하는 순간 사용자가 말을 고르기 시작한다. 판정을 여는 자리는 챕터를 닫을 때뿐이다.
3. **다음 질문을 정한다.** 도달이면 다음 주장으로. 미도달이면 각도를 바꿔 같은 주장을 다시 묻는다 — 자기 경험에서 예를 요구한다 → 이 주장이 틀리는 경우를 묻는다 → 원문 대목을 `[mm:ss]` 와 함께 보여주고 거기서 무엇이 걸리는지 묻는다. **3회 미도달이면** `## open_questions` 에 "주장 N — 3회 미도달, 쓴 각도: …" 를 적고 다음 주장으로 넘어간다.

**리서치는 원문에 답이 없을 때만.** 사용자가 물었든 네가 막혔든, 원문이 답하지 않는 물음이 나온 그때만 밖을 찾는다. 조건 없이 열어 두면 주장마다 웹을 뒤지느라 토의가 안 끝난다. 찾은 것은 문단이 아니라 **질문으로 끝낸다** — 완성해서 주면 사용자는 읽기만 한다. 요지와 출처는 `## 내 질문` 에 적는다.

**챕터를 닫을 때 매칭한다.** 그 챕터의 주장이 다 끝나면 거기서 처음으로 판정을 연다 — 네 이해와 사용자 이해가 **갈린 데만** 짚고 원문 근거를 `[mm:ss]` 로 댄다. 같은 데는 말하지 않는다. 갈린 내용은 그 주장의 `걸린 점:` 에 적고 다음 챕터로 간다.

사용자가 끊으면 — "여기까지", "그만", "다음에" — 남은 주장을 `## open_questions` 에 적고 5단계로 간다.

**완료 기준**: 주장마다 `판정: 도달` 이거나 그 번호가 `## open_questions` 에 있다. 닫은 챕터는 매칭까지 했다.

## 5. 마무리한다

[`references/closing.md`](references/closing.md) 를 읽고 그대로 한다 — 퀴즈, 정리 글, 닫기.

**재진입** — `done` 인 영상을 다시 부르면 다시 토의할지 묻는다. 한다면 `status: discussing` 으로 돌리고 `open_questions` 의 주장부터 시작한다. 새로 뽑을 주장이 있으면 그 챕터 끝에 더한다. 이전 `네 말` 은 지우지 않고 그 아래에 날짜를 붙여 덧붙인다.

**완료 기준**: `status` 가 `done` 이고 사용자가 퀴즈와 `open_questions` 를 받았다.
