# yt-grill

유튜브 영상 하나를 **원문으로 저장**하고, **토의**로 사용자가 제 말로 설명하게 만든 뒤, **정리**를 남기는 스킬. 규칙 원문은 [`SKILL.md`](SKILL.md), 파일 형식은 [`references/layout.md`](references/layout.md). 여기는 절차가 왜 이 모양인지의 근거를 적는다.

## 실측 — 원문 확보 (2026-09-06, 등급 ①)

환경: WSL2, uv 0.11.28, yt-dlp 2026.08.19, youtube-transcript-api 1.2.4. 시스템 설치 없이 `uv run` 캐시만 쓴다. ffmpeg 없음.

- **번역 트랙은 429 로 막힌다.** yt-dlp 에 `--sub-langs "ko,en"` 을 주면 원어가 아닌 쪽 요청에서 `HTTP Error 429` 로 죽는다(`-i` 없이는 exit 1). 같은 시각 원어 트랙은 정상이라 rate limit 이 아니라 번역 차단이다. transcript-api 는 있는 언어만 고르고 번역을 시도하지 않아 문제가 없다 — 본문을 transcript-api 로 받는 이유.
- **yt-dlp 의 자동자막 VTT 는 중복이 심하다.** 롤링 방식이라 같은 문장이 단어별 타임태그 줄과 평문 줄로 두 번 들어간다 — 영어 자동 138줄 중 86줄, 한국어 자동 171줄 중 104줄이 연속 중복. transcript-api 텍스트는 중복·태그 없이 1/10 크기.
- **원어 판별은 transcript-api 목록으로.** yt-dlp `--list-subs` 는 번역본을 맨 코드 `ko` 로, 원본을 `en-orig` 로 보여준다. 실제 사례 `IoI3LQUctkM`(조코딩, 한국어): 수동 `en-US`(업로드된 번역)와 자동 `en-US`·`id`·`ko` 가 있고 원어는 `ko` — "수동 우선"만 하면 영어 번역을 원문으로 저장한다. 스크립트는 yt-dlp 의 `language` 필드로 원어를 잡고 그 언어의 수동 > 자동 순으로 고른다.
- **크기.** 3분 영상 63줄 1.5천 자, 28분 강연(인프콘 2024 `0_PLNMjU948`) 609줄 1.5만 자. 자동자막 큐는 2~3초 단위라 문장 중간에서 끊긴다.
- **한국어 기술 강연의 자동자막 품질.** 읽히지만 영어 기술 용어가 깨진다 — "리액트 쿼리 캐시"가 "리 캐시", "success 이벤트"가 "섹스라는 이벤트", "axios"가 "엑시오스". 토의 중 이상한 단어는 원문 오류일 수 있다고 SKILL.md 2단계가 한 줄 덧붙이는 이유다. whisper 와의 비교는 아래.

## 실측 — 로컬 whisper (2026-09-06, 등급 ①)

Core Ultra 9 185H 22코어 + RTX 4070 Laptop 8GB, WSL2, faster-whisper, VAD 켬. 시스템 ffmpeg 없이 PyAV 가 m4a 를 바로 읽는다. 인프콘 2024 강연 27분 53초(`0_PLNMjU948`) 기준.

함정, 전부 실측:
- **turbo·large-v3 의 비배치 fp16 은 결정적으로 죽는다.** `CUDA failed with error an illegal memory access` 로 3/3. 같은 모델의 배치 파이프라인은 4/4 정상, small·medium 비배치는 정상. ctranslate2 4.8.2 + 이 드라이버/WSL2 조합의 커널 문제로 추정(감). 스크립트는 GPU 에서 배치만 쓴다.
- **pip 휠로 받은 CUDA 라이브러리는 로더가 못 찾는다.** `nvidia-cublas-cu12`, `nvidia-cudnn-cu12` 를 `uv run --with` 로 받아도 `libcublas.so.12 is not found`. 스크립트가 `.so` 를 `RTLD_GLOBAL` 로 미리 올리면 `LD_LIBRARY_PATH` 없이 된다 — 설치자에게 환경변수를 요구하지 않는 이유.
- **배치 출력은 세그먼트가 30초 단위다.** 27분이 55줄. 단어 타임스탬프를 켜고 문장 끝에서 끊으니 253줄, 전사 시간은 26.2초로 차이 없음.
- **VAD 가 음악을 전부 걸러 0줄을 낸다.** 스크립트는 0줄이면 VAD 를 끄고 다시 돈다.
- **언어를 강제하지 않는다.** 제목만 한국어고 음성이 영어인 영상(`8ucoskmA1yg`)에 `ko` 를 강제하니 한영 뒤섞인 결과에 속도도 나빠졌다. 자동 감지는 실제 음성 표본마다 0.99 로 맞췄다.
- `-x --audio-format wav` 는 ffmpeg 없이 안 되지만, PyAV 가 m4a 를 읽으므로 변환이 필요 없다.

구독(ChatGPT Plus, Claude Pro/Max)은 API 크레딧을 주지 않고 Anthropic 에는 음성 API 가 없으므로, 과금 없는 길은 로컬뿐이다(②).

## 실측 — 정확도 (2026-09-06, 등급 ①)

용어 grep 은 약한 잣대라 **사람이 만든 한국어 자막을 정답으로** 글자 오류율(CER: 정답 대비 치환·삭제·삽입 글자 수 / 정답 글자 수)을 쟀다. 후보 47개 중 수동 ko 자막이 있는 8개에서 채널이 다른 3개를 골랐다. 셋 다 축자형 자막이라 비교는 유효하고, 정답 자체의 오타·추임새 생략 때문에 바닥은 0 이 아니다. 공백·구두점 제거 후 jiwer.

| 영상 (채널, 연도, 길이) | 자동자막 | small GPU | large-v3-turbo GPU |
|---|---|---|---|
| Spring Data JPA (우아한테크, 2022, 18분) | 0.310 | 0.216 | 0.151 |
| Vue.js 입문 (T아카데미, 2019, 22분) | 0.308 | 0.226 | 0.196 |
| Redis (NHN FORWARD, 2021, 28분) | 자동자막 없음 | 0.137 | 0.109 |

**해석, 예상과 다른 것부터.**
- **자동자막의 주된 손실은 오타가 아니라 누락이다.** JPA 영상에서 정답 5,880자 중 1,177자(20%)가 문장 조각째 빠졌다 — "deleteAll 다음에 직접적으로 flush를 호출"이 "진리표를 다음에 강제 직접적으로 플러시적으로". whisper 는 삭제가 그 1/3.
- **순서는 세 영상·세 채널·두 시대에서 안 뒤집혔다.** turbo < small < 자동자막. 순서는 확신, 폭(몇 %p)은 영상마다 달라 반반.
- **절대값은 표기 규약으로 부풀려져 있다.** 정답이 영문 용어를 로마자로 쓰고(BRPOP, flush) whisper 는 "BR pop", "플러시"로 써서 틀린 걸로 센다. 한글만 남기면 whisper 는 0.02~0.04 내려가고 자동자막은 그대로 — 자동자막 오류는 진짜 오인식이다. Redis 명령어(LPUSHX)는 whisper 도 못 잡는다.

**원문 차이가 스킬 산출물을 바꾸는가.** 인프콘 강연의 자동자막 원문과 whisper small 원문을 각각 주고 3단계(요약·핵심 주장)를 sonnet 으로 2판씩 뽑았다. 네 판이 같은 주장 집합을 냈고, 자동자막 쪽도 "리액트 쿼리의 쿼리 캐시로 에러를 전역에 모은다"를 깨진 원문에서 문맥으로 복원했다. 즉 뼈대만 보면 자막으로 충분하다 — 영상 하나 기준이고, 20% 누락이 핵심 주장에 걸리는 영상에서는 다를 수 있다. 전사의 이득은 사용자가 원문을 읽을 때와 토의 중 인용문이 사용자 눈에 보일 때다.

**결정.** 처음 설계는 "자막 기본, 전사는 대체"였다. 오류율 절반과 GPU 1분/시간이 나와서 **GPU 가 있으면 turbo 전사 기본**으로 바꿨다. GPU 가 없으면 자막 기본이다 — 시간당 7~12분을 기본으로 물리기엔 비싸다(반반). 판 수: 영상 3개 각 1회.

**해석.** 유튜브 챕터는 토의 단위로 쓸 수 없다 — 3분 영상에 9개다. 그리고 4개 중 1개는 아예 없다. 그래서 재료로만 쓴다: 제목이 화제 전환을 알려 주니 3~5개로 묶고, 없으면 원문에서 나눈다. `UNzCG3lw6O0` 의 10개는 강연의 4단 체크리스트(트리거·구조·스티어링·가지치기)로 묶이고, 그 4개가 실사용에서 뽑은 주장 5개와 거의 1:1이었다 — 20분짜리에서는 챕터 축이 사실상 주장 축이다.

## 판정 규칙 A/B (2026-09-06) — 세부 정의는 no-op, 빼기로

4단계 "네 말로 설명됐다" 판정에 세부 정의(도달 = 자기 예·비유·다른 말·조건·반례 / 미도달 = 되풀이·"이해했다"뿐·요약만)를 둘지가 설계 단계에서 유일하게 남긴 규칙 질문이었다. 규칙은 넣기 쉽고 빼기 어려우니 결과가 갈릴 때만 넣는다.

**방법.** 3단계까지 끝난 `notes.md`(조코딩 `IoI3LQUctkM`, 주장 3개)와 원문을 주고, "주장 1을 네 말로 하면?" 에 대한 사용자 답 하나를 넣어 **한 턴**을 수행하게 했다. sonnet, 셀당 3판, 작업 디렉토리 분리, 프롬프트는 "스킬 4단계가 시키는 대로 이번 턴을 수행하라"만. A 는 세부 정의 대신 "제 말로 설명했으면 도달이다" 한 줄, B 는 세부 정의 블록. 시나리오는 셋: S1 영상 문장을 거의 그대로 되풀이, S2 자기 예 + 다른 말 + 조건 짚기, S3 "네 이해했어요" + 한 줄 요약. 합격 기준은 돌리기 전에 등록했다 — S1 에서 B 미도달 ≥ 2/3 이고 A ≤ 1/3 이면 채택, A 도 ≥ 2/3 이면 no-op.

| 시나리오 | A 미도달 | B 미도달 | 다음 질문이 주장 1에 머묾 (A / B) | 판정을 입 밖에 냄 (A / B) |
|---|---|---|---|---|
| S1 되풀이 | 3/3 | 3/3 | 3/3 / 3/3 | 0/3 / **1/3** |
| S2 바꿔 말하기 | 0/3 (도달 3/3) | 0/3 (도달 3/3) | 0/3 / 0/3 | 0/3 / 0/3 |
| S3 요약만 | 3/3 | 3/3 | 3/3 / 3/3 | 0/3 / **1/3** |

**해석.** 1차 지표가 18판 전부 같다 — 세부 정의 없이도 되풀이와 요약만을 미도달로, 자기 예를 도달로 갈랐고, 다음 질문도 전 판이 "네 주변에서 본 예를 들어봐" 각도로 갔다. 예상과 달랐던 것은 2차 지표다. B 는 6판 중 2판이 "그거 영상이 한 말이랑 거의 똑같아", "그건 영상이 한 말을 그대로 줄인 거에 가까워" 라고 **판정을 사용자에게 말했다** — 같은 문서에 "판정은 머릿속에서만 한다" 가 있는데도. A 는 0/6. 세부 정의가 판정을 바꾸지는 않으면서 판정을 발화하게 만든 쪽으로 기울었다. 기준대로 no-op 이고 부작용까지 있으니 뺐다. `네 말` 기록은 18판 전부 됐다.

**한계.** 살짝만 바꿔 말한 되풀이 같은 경계 시나리오는 안 쟀다 — 거기서 갈릴 수 있으나, 등록한 기준에 없던 시나리오를 결과 보고 더하지 않는다. 셀당 3판이라 2/6 vs 0/6 은 방향만 말한다. 판정 비공개 위반이 실사용에서 관찰되면 그때 이 자리로 돌아온다.

## 한계

- A/B 는 4단계의 판정 기준 한 블록만 쟀다. 한 턴 한 질문, 즉시 기록, 판정 비공개는 add-experience 에서 빌려온 규칙이고 여기서 다시 재지 않았다.
- 토의 전체(여러 턴에 걸친 진행·끊기·재진입)는 시뮬레이션하지 않았다. 실사용에서 관찰한다.
- GPU 경로는 이 머신(RTX 4070, WSL2, 드라이버 591.74) 하나에서만 검증했다. 다른 GPU·드라이버에서 비배치 크래시가 같은 방식으로 나는지, 배치가 같은 방식으로 피해 가는지는 모른다. GPU 전사가 죽으면 스크립트는 자막으로, 자막도 없으면 CPU 로 내려간다.
- 자막이 정말 없는 영상을 찾지 못해 CPU whisper 경로는 `--whisper` 강제로만 검증했다.
- 전사 시간은 같은 조건에서 1.5배 흔들렸다(CPU small 0.11~0.20, small GPU 0.04~0.10). 노트북 열·전력 관리로 추정하지만 재지 않았다. turbo 배치는 0.016~0.022 로 안정.
- 챕터 축·매칭·퀴즈는 A/B 로 재지 않았다. 특히 **챕터 끝 매칭이 다음 챕터의 답을 오염시키는지**는 안 쟀다 — 판정 발화가 사용자 말을 고르게 만든다는 게 아래 A/B 가 잡은 부작용이라 같은 위험이 있다.
- 챕터 표본은 4개(한국어 3, 영어 1)다. 챕터가 있는 비율과 밀도는 이 표본에서만 본 것이다.
- **GPU 배치 전사가 한 번 죽었다** (2026-09-07, 6분 영상, `CUDA failed with error an illegal instruction was encountered`, exit 134). 자막으로 폴백해 저장은 됐고, 같은 영상 재실행은 7.2초에 정상이었다. 위 표의 "배치 4/4 정상" 은 그대로지만 배치도 드물게 죽는다.
- 자막 확보는 유튜브 쪽 변화(429 정책, PO 토큰)에 따라 깨질 수 있다. 깨지면 `uv run yt_grill.py info <url>` 의 `transcripts` 가 비는 것으로 드러난다.
