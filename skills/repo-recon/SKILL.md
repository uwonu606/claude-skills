# 레포 답사

낯선 레포를 **답사**한다. 레포가 자기를 설명해 둔 글을 옮겨 적는 게 아니라, 직접 걸어 보고 다음 사람이 걸을 **동선**을 그려 온다.

답사기는 두 가지를 갖고 돌아온다 — 이 레포를 **읽는 법**, 그리고 이 레포에서 **가져갈 것**. 가져갈 것을 가르는 축이 **관행이냐 특유냐**다. 널리 쓰여서 배워 두면 다른 레포에서도 쓰는 것인가, 이 레포만의 선택인가.

파는 일 자체는 이미 잘 된다. 이 스킬이 정하는 건 **무엇을 갖고 돌아오느냐**다.

## 1. 목적을 한 줄로 고정한다

무엇에 쓸 답사인지 먼저 적는다. 사용자가 말했으면 그대로 쓰고, 안 했으면 **"처음 보는 개발자가 이 코드베이스를 이해한다"** 로 잡고 그렇게 잡았다고 밝힌다.

이 한 줄이 산출물의 성격을 바꾼다. 목적이 없으면 답사기가 오리엔테이션이 아니라 총평·리스크 평가로 기운다 — 그때 제일 먼저 빠지는 게 동선과 함정이다.

**완료 기준**: 목적 한 줄이 답사기 맨 위에 있다.

## 2. 레포가 이미 써 둔 것부터 건진다

같은 일을 두 번 하지 않기 위해서다. `README`·`CONTEXT`·`AGENTS`/`CLAUDE`·`docs/`·ADR·다이어그램·이슈 파일을 훑어 **어떤 설명이 이미 있는지** 목록으로 낸다.

그리고 각각에 **지금도 맞는지**를 붙인다. 문서는 낡는다. 낡음에도 종류가 있어서 구분해 적는다.

| 표시 | 뜻 |
|---|---|
| 살아 있음 | 코드와 대조해 어긋나지 않았다 |
| 드리프트 | 코드가 앞서갔고 문서가 안 따라왔다 |
| 일부러 동결 | 그 시점의 스냅샷으로 남긴 것이라 고칠 대상이 아니다 |

**완료 기준**: 설명 문서가 전부 나열됐고 각각에 살아 있음/드리프트/동결이 붙었다.

## 3. 동선을 짠다

읽는 순서를 단계로 낸다. 각 단계는 **읽고 나면 무엇을 할 수 있게 되는지**로 끝난다 — "구조를 본다"가 아니라 "기능 하나가 어느 파일들을 거치는지 짚을 수 있다".

대략의 소요 시간을 붙인다. 어디까지가 오늘 몫이고 어디부터가 나중인지 판단할 재료가 된다.

목적(#1)이 좁으면 동선도 좁힌다. 전체 이해가 목적이 아니면 곁길은 "필요할 때" 단계로 미룬다.

**완료 기준**: 단계마다 산출 능력 한 줄과 시간 추정이 있다. 1단계는 레포를 열자마자 바로 시작할 수 있는 것이다.

## 4. 내려가면서 관행과 특유를 가른다

구조를 위에서 아래로 훑되, 눈에 걸리는 방식마다 네 가지를 채운다. **이름을 못 붙이면 배울 수 없다** — 이름이 있어야 나중에 찾아볼 수 있다.

| 칸 | 채우는 것 |
|---|---|
| 확립된 이름 | ADR, walking skeleton, 포트와 어댑터, Conventional Commits, 값 객체, 점진적 공개. 없으면 "이름 없음"이라고 적는다 |
| 관행이냐 특유냐 | 널리 쓰인다 / 이 바닥에선 흔하다 / 이 레포 특유. 널리 쓰인다고 할 때는 출처를 댄다 (누가 언제 제안했는지, 어디가 쓰는지) |
| 장단점 | 무엇을 사고 무엇을 치렀는지. 단점 없는 항목은 아직 덜 본 것이다 |
| 이 레포의 변형 | 표준을 그대로 쓰지 않았으면 어디를 어떻게 틀었는지 |

README 작성 방식, 문서 배치, 커밋·브랜치 규약, 테스트 짜임도 같은 대상이다. 코드만 보지 않는다.

**의도는 추측으로만 적는다.** 코드가 **무엇을 하는지**는 읽으면 확정되지만 **왜 그렇게 했는지**는 아니다. 둘을 한 문장에 섞지 않고, 이유 쪽에는 근거 등급을 붙인다. 커밋 메시지·ADR·주석에 이유가 적혀 있으면 그건 추측이 아니라 인용이다.

**완료 기준**: 이름 붙인 항목마다 네 칸이 채워졌거나 빈 칸이 왜 비었는지 적혀 있다. 관행과 특유가 각각 하나 이상 있다 — 한쪽만 나왔으면 덜 본 것이다.

## 5. 답사기를 레포 밖에 남긴다

받아 온 레포는 남의 것이니 건드리지 않는다. 답사기는 레포 **밖**에 쓰고 경로를 알린다. 사용자가 자리를 정해 두지 않았으면 어디에 쓸지 먼저 묻는다.

**시작할 때 `git status --porcelain` 을 찍어 두고 끝에 다시 찍어 비교한다.** 받아 온 레포는 처음부터 더러운 경우가 흔해서, 비어 있는지가 아니라 **내가 들어오기 전과 같은지**가 기준이다. 테스트나 빌드를 돌렸으면 gitignore 아래에 산출물이 남으므로 git 이 못 본다 — 무엇을 돌렸는지 답사기에 적는다.

끝에 **읽은 깊이**를 남긴다 — 전문을 읽은 파일, 일부만 본 파일, 목록·통계로만 확인한 것. 답사기를 이어 읽을 사람이 어디를 믿고 어디를 다시 봐야 하는지 아는 유일한 단서다.

**완료 기준**: 답사기가 레포 밖 파일로 남았고, 읽은 깊이가 구분돼 있고, `git status --porcelain` 이 시작 때와 같다.
