# repo-recon

낯선 레포를 답사해 읽기 동선과 배울 거리를 뽑는 사용자 호출 스킬. 절차 원문은 [`SKILL.md`](SKILL.md), 여기는 왜 이 모양인지의 근거를 적는다.

## 왜 이 모양인가 — 능력이 아니라 스펙을 담는다

**에이전트는 시키면 이미 잘 판다.** 이 스킬은 파는 법을 가르치지 않는다. 무엇을 갖고 돌아올지만 정한다.

만들기 전에 스킬 없는 기본선을 8회 재봤다. **출발 가설이 틀렸다.** "기본 탐색은 README를 바꿔 쓰고 만다"고 봤다. 기본선은 소스 파일을 8~45개 경로로 인용했고, 찍어 본 수치 주장 8개가 전부 정확했다.

그래서 이 스킬의 값어치는 **저장된 스펙** 하나다. 6항목 요구를 레포마다 다시 조립하지 않아도 된다는 것. 사용자 호출(`disable-model-invocation: true`)이라 **컨텍스트 부하는 0이다.** 치르는 건 "이 스킬이 있다"를 기억하는 인지 부하뿐이다.

## 1라운드 — 스킬이 필요한가 (2026-09-06, opus, 8런)

사전 등록한 합격 기준: 3개 조건에서 각 2/2로 소스 5개 이상 인용 + 문서 밖 사실 3개 이상 + 확인/추측 구분이면 **스킬 불필요**.

| 조건 | 소스 인용 | 문서 밖 사실 | 주제 커버리지 | 2회 반복 일치 |
|---|---|---|---|---|
| 대형 다중스택 (Java 335 + tsx 35) | 21~28 | 20~27 | 9~10/10 | 9/10 |
| 중형 단일스택 (Java 103) | 8~12 | 4~8 | 9/10 | 10/10 |
| 산문 (md 112) | 44~45 | 4~5 | 8~9/10 | 9/10 |

정확성은 표본으로 대조했다 — ADR 11개, 프로덕션 4,150줄 / 테스트 4,233줄, `FileTools` 445줄, `index.html` 495줄, `ddl-auto: none`, 테이블 19개. **8개 전부 일치.**

**갈린 건 목적 한 줄뿐이다.** 프롬프트에 목적("처음 보는 개발자가 이해하는 데 필요한")을 주면 커버리지 8~10/10, 안 주면 **6~7/10** 으로 떨어진다. 목적이 없으면 산출물이 오리엔테이션에서 총평·리스크 평가로 기울고, 그때 빠지는 게 읽기 순서·도메인 용어·함정이다.

## 2라운드 — 6항목 스펙을 주면 어디까지 하나 (3런)

기존 문서 지목 / 관행 판별 + 장단점 / 패턴 이름 / 의도 추측 표시를 사전 등록하고 3개 레포에 각 1회.

**3/3 전부 통과.** 기본선이 ADR을 Michael Nygard 2011 출처까지 대고 장단점을 주고 이 레포가 표준에서 어떻게 벗어났는지까지 짚었다. 능력은 충분하다는 뜻이고, 그래서 스킬은 스펙만 담는다.

## 뺀 것과 이유

**no-op 은 넣지 않는다** — 부하만 치르고 행동은 안 바뀌는 줄들이다.

| 뺀 것 | 근거 |
|---|---|
| 파일 경로 인용, 사실 대조, 흐름 추적, 진입점 찾기 | 8/8 런에서 시키지 않아도 나왔다 |
| 확신 등급(확신·반반·감) 붙이기 | 전역 `CLAUDE.md` 가 이미 시킨다. 프로브들이 저절로 썼다 |
| "기본 브랜치가 읽을 브랜치라고 가정하지 마라" | 2/2 로 스스로 잡았다 — `main` 이 31커밋 뒤처졌고 실물은 피처 브랜치에 있다는 것까지 |

## 넣은 것과 근거

| 넣은 것 | 근거 |
|---|---|
| 목적 한 줄 고정 (#1) | 커버리지 6~7 → 8~10 을 움직인 유일한 변수 |
| 동선 (#3) | 목적 없는 런에서 통째로 빠졌다 |
| 관행/특유 네 칸 (#4) | 요구의 본체. 시키면 되고 안 시키면 안 된다 |
| 읽은 깊이 구분 (#5) | 3런 중 1회만 나왔다. 제일 흔들리는 항목 |

## 실행 테스트

측정에 안 쓴 **4번째 스택**(Unity C#, 533 파일)에 스킬을 그대로 돌렸다. 동선 5단계, 관행 3 / 특유 6 으로 갈렸고 `CLAUDE.md` 판본이 셋 돌아다니는 것을 잡아냈다.

**이 실행이 5단계의 완료 기준을 고쳤다.** 원래 기준은 "`git status --porcelain` 이 비어 있다"였고, 두 군데서 틀렸다.

받아 온 레포에는 8월부터 있던 untracked 파일이 있어 애초에 비지 않는다. 그리고 에이전트가 돌린 테스트의 빌드 산출물은 gitignore 아래라 git 이 보지도 못한다. 기준을 **시작 때와 같은가**로 바꿨다.

## 한계
