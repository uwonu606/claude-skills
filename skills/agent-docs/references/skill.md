# 스킬일 때

문서가 스킬일 때만 달라지는 것이다: 누가 부르는가, description, 언제 쪼개는가. 나머지는 `SKILL.md` 의 단계를 그대로 따른다.

## 누가 부르는가

| | 에이전트가 스스로 부른다 | 사람만 부른다 |
|---|---|---|
| frontmatter | `disable-model-invocation` 이 없거나 `false` | `disable-model-invocation: true` |
| description 이 context 에 실리는가 | 세션 내내 실린다 | 실리지 않는다 |
| 다른 스킬이 부를 수 있는가 | 있다 | 없다 |
| 치르는 값 | 매 턴 context 를 쓴다 | 사람이 이름을 기억해야 한다 |

에이전트가 스스로 닿아야 하거나 다른 스킬이 불러야 할 때만 에이전트가 부르는 스킬로 둔다. 손으로만 부르는 스킬은 사람만 부르는 스킬로 두어 context 를 쓰지 않게 한다.

사람만 부르는 스킬 둘이 같은 참고를 쓰면, 그 참고는 스킬 밖의 파일에 두고 양쪽에서 가리킨다. 두 스킬은 서로를 부를 수 없기 때문이다.

사람만 부르는 스킬이 기억하기 어려울 만큼 늘면 router 스킬 하나를 둔다. router 는 나머지 스킬의 이름과 각각을 쓸 때를 적은, 사람만 부르는 스킬이다. router 는 안내만 하고, 부르는 것은 사람이다.

## description

사람만 부르는 스킬의 description 은 가리키는 문장이 아니라 사람이 읽을 한 줄 요약이다. 읽을 조건은 적지 않고, `SKILL.md` 2단계의 완료 기준도 걸지 않는다.

에이전트가 부르는 스킬의 description 은 스킬 본문을 가리키는 문장이다. `SKILL.md` 2단계의 규칙을 그대로 적용하고, 두 가지를 더 본다.

**다른 스킬과 조건이 겹치는지 본다.** 스킬은 description 으로 발동을 다툰다. 이 세션의 스킬 목록에 같은 요청에 걸리는 description 이 있으면, 둘을 합치거나 어느 쪽이 무엇을 맡는지를 한 구절로 적는다.

**목록에 실제로 실렸는지 본다.** Claude Code 는 스킬 목록이 예산을 넘으면 덜 불린 스킬의 description 부터 빼고 이름만 싣는다. 새 세션의 스킬 목록에 이 스킬이 이름만 있으면 빠진 것이다. 예산의 크기와 올리는 설정은 Claude Code 문서 skills 페이지의 "Skill descriptions are cut short" 절에 있다.

## 언제 쪼개는가

스킬을 둘로 쪼개면 항상 실리는 description 이 하나 는다. 쪼개는 경우는 둘이다.

- 그 부분만 따로 부르는 낱말을 사용자가 프롬프트에서 실제로 쓴다.
- 다른 스킬이 그 부분을 불러야 한다.

뒤 단계 때문에 앞 단계를 서두를 때의 쪼개기는 `SKILL.md` 3단계에 있다.

**완료 기준**: 사람만 부르는 스킬이면 description 이 한 줄 요약이다. 에이전트가 부르는 스킬이면, 조건이 겹치는 스킬을 찾아본 결과와 description 이 목록에 실렸는지 새 세션에서 확인할 일을 사용자에게 알렸다.
