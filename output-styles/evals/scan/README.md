# scan 시험

scan 의 줄을 넣거나 뺄 때, 바꾸기 전 판(A)과 바꾼 판(B)을 `../layered/run.py` 로 같은 과제에 돌리고 `score.py` 로 점수를 매긴다. `../layered/check.py` 는 layered 의 층 골격을 세므로 scan 에는 쓰지 않는다.

```bash
python3 ../layered/run.py --out "$OUT" --task propose --n 12 A=before.md B=after.md
python3 score.py "$OUT" --judge
```

`--out` 은 저장소 밖에 둔다. 저장소 안의 작업 폴더에서는 이 프로젝트의 auto memory 가 두 판 모두에 읽혀 메모리에서 온 줄의 시험이 무효가 될 수 있다.

## 지표

| 지표 | 세는 법 |
|---|---|
| `dropped` | `덜어낸 것:` 으로 시작하는 줄이 있는 답 |
| `dup_in_body`, `non_alternative` | 그 줄의 이름이 본문에 이미 나왔거나 실제 대안이 아닌 답. LLM 판정 |
| `all_five` | 실측 답에 무엇을 쟀나·방법·표·해석·한계가 모두 있다. 표는 문자열로, 나머지는 LLM 이 원문을 인용하고 코드가 원문에서 위치를 찾는다 |
| `ordered` | 다섯 요소가 그 순서로 나온다 |
| `lead_is_answer` | 첫 문장이 어느 쪽이 나은지 말한다 |
| `ran_script` | 도구 기록(`.jsonl`)에 `sim.py`·`bench.py` 실행이 있다 |
| `judge` | 같은 회차 번호의 A·B 답을 순서를 번갈아 블라인드로 보이고, CLAUDE.md 를 붙인 판정자가 고른다 |

## 2026-10-26 회차: 덜어낸 것 줄과 #실측 절

A 는 커밋 1c4102f 의 scan.md, B 는 #설명 끝에 `덜어낸 것:` 줄(줄 A)과 #실측 절(줄 B)을 넣은 판이다. 판마다 12회, Opus 5.5. 아래 기준은 A·B 본 시험을 돌리기 전에 적었다.

줄 B 의 주 지표는 A 만 4회 먼저 돌려 정했다. A 의 `all_five` 가 1/4(빠진 것은 무엇을 쟀나 3/4), `ordered` 가 0/4 라서 미리 정한 규칙(A 가 절반 이하면 `all_five`)대로 `all_five` 로 둔다.

| 줄 | 과제 | 통과 |
|---|---|---|
| A | `propose` | `dropped` 가 B 에서 많고 Fisher p < 0.05 |
| A | `propose` | B 의 `dup_in_body`, `non_alternative` 가 각각 2/12 이하 |
| A | `fact` | B 의 `dropped` 가 0/12 |
| B | `report` | `all_five` 가 B 에서 많고 p < 0.05. `ran_script` 가 거짓인 회차는 두 판 모두에서 빼고 센다 |
| B | `report` | `lead_is_answer` 가 B 에서 유의하게 적지 않다(한쪽 Fisher p < 0.05 면 해) |
| B | `report-holdout` | 본 시험 뒤 한 번만, 판마다 8회. B 의 `all_five` 가 A 이상 |
| 둘 다 | 모든 과제 | 글자 수 가운데값 B/A 가 1.3 이하(`report` 과제는 1.6 이하) |
| 둘 다 | 모든 과제 | 블라인드 판정에서 B 가 이긴 수가 한쪽 부호 검정 p < 0.05 로 낮지 않다 |

`explain` 의 `dropped` 는 보조로만 본다. 해 점검에 걸리면 두 줄을 따로 넣은 판으로 나눠 다시 잰다.

### 1차 결과 뒤에 더한 확인 시험

1차에서 줄 B 의 주 지표 `all_five` 는 A 9/12, B 11/12(p=0.59)로 효과가 없었고, 보조 지표 `ordered` 는 3/12 → 10/12(p=0.012)였다. 결과를 본 뒤 고른 지표라서 1차 수치로는 판정하지 않고, 새 표본으로 다시 잰다. 아래는 확인 시험을 돌리기 전에 적었다.

| 줄 | 과제 | 통과 |
|---|---|---|
| B | `report` 새 12회씩 | `ordered` 가 B 에서 많고 Fisher p < 0.05 |
| B | `report-holdout` 8회씩 | 처음 정한 대로 B 의 `all_five` 가 A 이상. `ordered` 는 보조로 찍는다 |
| A | `explain`·`propose` (진단) | 판정이 아니라 진단이다. B 답에서 `덜어낸 것` 줄만 지우고 같은 쌍을 다시 블라인드로 판정한다. 그래도 B 가 지면 해는 그 줄 밖에 있고, 비기면 진 까닭은 그 줄이다 |

### 결과

Opus 5.5, 작업 폴더는 저장소 밖. 수치는 B 를 지지하는 쪽의 Fisher 양쪽 p 다.

| 줄 | 과제 | 지표 | A | B | p | 판정 |
|---|---|---|---|---|---|---|
| A | `propose` | `dropped` | 0/12 | 12/12 | <0.001 | 통과 |
| A | `propose` | `dup_in_body` · `non_alternative` | – | 1/12 · 0/12 | – | 통과 |
| A | `fact` | `dropped` | 0/12 | 0/12 | – | 통과 |
| B | `report` 1차 | `all_five` | 9/12 | 11/12 | 0.59 | 탈락 |
| B | `report` 확인 | `ordered` | 1/12 | 10/12 | 0.001 | 통과 |
| B | `report-holdout` | `all_five` · `ordered` | 6/8 · 0/8 | 8/8 · 6/8 | 0.47 · 0.007 | 통과 |

해 점검은 모두 통과했다. 글자 수 비는 `propose` 1.00, `explain` 1.09, `fact` 0.75, `report` 1.07·1.11, `report-holdout` 1.13 이다. 블라인드 판정(B:A)은 `propose` 4:8(p=0.19), `explain` 3:9(p=0.073), `fact` 5:7, `report` 8:4·7:5, `report-holdout` 4:4 였다.

- `explain`·`propose` 에서 B 가 진 까닭은 `덜어낸 것` 줄이다. 그 줄만 지운 B 를 다시 판정하면 두 과제 모두 6:6 이다. 판정자는 이 줄을 "맥락 없는 목록"으로 읽었고, 사용자가 이 줄로 되묻는다는 것은 판정자 프롬프트에 넣지 않았다.
- 줄 B 가 고친 것은 요소의 순서다. 요소가 빠지는 실패는 A 에서도 드물었고(1차 3/12, 확인 4/12), 빠진 것은 대개 무엇을 쟀나였다.
- `덜어낸 것` 줄이 실측 답에도 붙는다(7/12~8/12). 그 이름 가운데 실제 대안이 아닌 것(더 해 볼 실험)이 있는 답이 1차 5/12, 확인 3/12, holdout 0/8 이다.
- 결과를 본 뒤 고친 것: `ran_script` 패턴이 `python3 -I sim.py` 를 놓쳐 1차에서 A 4, B 1 회차가 빠졌다. `.jsonl` 로 실제 실행을 확인하고 패턴을 고쳤다. 고치기 전 `all_five` 는 A 7/8, B 10/11 로 판정은 같다.
- 사전 4회로 주 지표를 고르는 규칙은 빗나갔다. A 의 `all_five` 가 사전 1/4, 본 시험 9/12 였다(p≈0.07). 다음에는 사전 시험을 8회 이상 돌리거나 이유를 들어 지표를 고른다.

### 결정

줄 A 만 넣었다. 줄 B(#실측 절)는 시험 기준을 통과했지만 뺐다(2026-10-27 사용자). 사용자는 확인 시험의 A-1(순서 지표 탈락)과 B-10(통과)을 직접 읽고 A-1 이 더 이해하기 쉽다고 판단했다. A-1 은 결론 → 표 → 물음 하나씩 맡은 문단으로 논리를 따라가고, B-10 은 틀이 정한 칸을 채우느라 문단 하나에 여러 물음을 담았다. 줄 B 가 겨냥한 실패(무엇을 어떻게 돌렸는지가 빠짐)도 A-1 에는 없었다. 표 앞 문장이 명령과 조건으로 그것을 이미 밝혔다. `ordered` 는 틀의 모양을 셌지 이해를 재지 않았다.
