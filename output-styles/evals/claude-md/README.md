# CLAUDE.md 시험

전역 CLAUDE.md 와 그 둘레(출력 스타일, 스킬, 메모리)의 줄을 넣거나 바꿀 때, 바꾸기 전 판(A)과 바꾼 판(B)에 같은 과제를 주고 행동을 견준다.

```bash
AB_BASE=~/.claude/CLAUDE.md AB_REPS=12 python3 ab.py run scope1        # CLAUDE.md 후보
AB_REPS=12 python3 evaluate.py scope1
python3 ab2.py run labnotes && python3 ab2.py eval labnotes            # 스킬·메모리·스타일 후보
python3 pathrule.py                                                    # user 수준 path-scoped rule 로드 확인
python3 ab3.py run && python3 ab3.py eval                              # 제안 규칙(문제·제안·근거·포기하는 것) 준수
```

- `ab.py` 는 `claude -p --setting-sources project` 로 사용자 CLAUDE.md 를 빼고, 판의 본문을 `--append-system-prompt` 로 넣는다. 두 판에 layered 스타일 본문과 `language: korean` 을 같이 싣는다.
- 판마다 작업 폴더를 따로 만든다. 결과는 `AB_OUT`(기본 `/tmp/claude-md-ab`)에 쌓이고, 저장소에는 두지 않는다.
- `VARIANTS` 와 `ab2.py` 의 바꿀 문구는 2026-10-11 회차의 것이다. 이미 반영된 문구는 바꾸기 전 판(`AB_BASE`)을 그 시점 파일로 주어야 다시 돈다.
- `pathrule.py` 는 `~/.claude/rules/` 에 이 시험 전용 이름(`zz_ab_probe_*.py`)에만 걸리는 규칙을 잠깐 두고, 끝나면 지운다.

## 판정 기준

결과를 보기 전에 정하고, 결과를 보고 바꾸지 않는다. 기준은 [`../layered/README.md`](../layered/README.md) 의 줄을 남기는 기준을 따른다.

- 판마다 12회 이상 돌린다. 3회짜리 결과는 방향만 본다. 2026-10-11 에 3회에서 12→0 으로 보였던 차이가 12회에서는 6/36 대 5/36 이었다.
- 줄을 더하거나 행동을 바꾸는 후보는 겨냥한 지표에서 Fisher 정확 검정 p < 0.05 이고, 출력 토큰 가운데값이 A 의 1.3배를 넘지 않아야 넣는다.
- 부딪히는 문구를 지우는 후보는 겨냥한 실패가 두 판 모두 0 이면 통과로 보되, 다른 지표가 나빠지지 않는지 답을 읽어서 본다.
- 판정은 파일 diff·출력 문자열로 먼저 하고, 그럴 수 없는 과제만 LLM 판정(`evaluate.judge`)을 쓴다.

### 제안 규칙 재시험(`ab3.py`)

앞 회차의 제안 과제("팀에 어떻게 말할지 제안해줘")는 세 가지로 흔들렸다. 답에 어시스턴트의 제안과 팀에 보낼 초안이 함께 있어 판정이 어느 쪽을 볼지 갈렸다. 스타일이 시킨 `모르는 것:`·머리말이 실패로 섞였다. 조건 넷을 한 번에 묻는 판정이 같은 모양에 다른 답을 냈다. 그래서 어시스턴트가 직접 제안하는 과제 넷을 판마다 10회씩 돌리고, LLM 은 네 요소가 처음 나오는 곳을 원문 인용으로만 뽑게 했다. 순서와 준수는 스크립트가 계산한다.

| 비교 | 준수(넷 모두, 근거·포기하는 것이 제안 뒤, 라벨 없음) | 라벨 | 문제가 제안보다 먼저 |
|---|---|---|---|
| CLAUDE.md:12 화살표(A) 대 쉼표(B), layered | 27/40 대 33/40, p=0.20 | 11/40 대 7/40 | 1/40 대 0/40 |
| scan 정리 전(A) 대 정리 뒤(B) | 27/40 대 24/40, p=0.64 | 4/40 대 11/40, p=0.083 | 0/40 대 1/40 |

- 두 비교 모두 효과가 없다. 앞 회차의 8→5, 9→7 은 과제 탓으로 본다.
- scan 정리 뒤 라벨이 늘어난 쪽으로 기울었다. 늘어난 것은 요소 이름을 머리말로 단 답이다(`**원인**`, `**포기하는 것**`). 지운 scan 줄의 "문단 안 문장 순서로"가 이를 막았을 수 있다. 유의하지 않아 지금은 두고, 다시 볼 신호로 남긴다.
- "문제가 제안보다 먼저"는 160회 중 2회다. CLAUDE.md:7 "첫 문장은 답만"과 스타일의 "첫 문장이 답이다"가 이 순서를 이긴다. CLAUDE.md:12 의 나머지 몫(근거·포기하는 것을 제안 뒤에, 라벨 없이)은 뺀 판과 견주지 않았다. 효과가 애매해 no-op 으로 보고 지웠고(2026-10-11 사용자), layered 의 "4요소로"도 함께 뺐다.
